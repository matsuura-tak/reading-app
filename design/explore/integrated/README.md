### 画面の流れ（v1）
- 毎晩：ロック画面のウィジェット → 押す → しおりの画面 → 伏せる（または「読み始める」）→ 読書中の画面 → 「終える」→ しおりを挟む → 読書の結果 → 閉じる（しおりの画面へ）
- 読み終えた夜：しおりの画面の「読み終えた」→ 読み終えた画面（1つのスクロールで、奥付 → 次の1冊 → カード）→「この本を読む」（翌晩から、その本がウィジェットに出る。最初は書名だけ）
- 登録：本棚か、本がないときのしおりの画面から → バーコードを続けて読む →「2冊を本棚に加える」

## 気をつけたアクセシビリティ
- **縦書きの読み上げ**：ウィジェットとしおりの画面の一行は、1字ずつの組みを読み上げから隠し、全体を1つのラベルにします（PRD 12）。例：「小さな舟、43ページ。雨は、まだやまなかった。舟は岸にあった。」。しおりの画面の読み上げの順は、本棚、設定、書名と著者、一行、ページ、どこまで読んだかを入れる、読み終えた、読み始める、伏せて置いても始まります。④ の列の枠は、「6列のうち6列目、選択中、灯を消すと、川の音だけが残った。」のように、位置と状態と中身を読みます。
- **大きい文字（AX5）**：しおりの画面の一行は、AX のサイズでは横書きに切り替えます（縦書きの1列に字が入らなくなるため）。「どこまで読んだかを入れる」と「読み終えた」の横並びは縦に並べます。⑥ の行のボタンは、書名と理由の下に回します。ウィジェットに入りきらないときは、書名とページだけにします（integrate-designer の 1-1。G1 で決める）。⑤ の奥付は、名前と値を縦に並べます。
- **ダーク**：夜に使うので、①と②はダークを描きました。ロック画面は壁紙しだいで、ダークの図は夜の壁紙の例です。読み終えのカードの画像は、送る先で見え方が変わらないよう、いつも白地にします。
- **動きを減らす設定**：独自の動きは描いていません。画面の出入りはシステムのシートと押し出しに任せます。伏せて始まったことは、触覚、読み上げ、起こしたときの読書中の画面の3つで伝え、動きに頼りません（PRD 12）。
- **透明度を下げる設定**：ツールバーのボタン（Liquid Glass の想定）はシステムが不透明にします。内容の層（一行、奥付、一覧）には素材を使っていません。
- **色だけに頼らない**：④ の選んだ列は、太い枠と「選択中」の文字で示します。⑦ の読めたバーコードは、枠と「読みました」の文字で示します。⑥ の本棚にない本は、「本棚にない本」の文字と、ボタンの言葉（積読に加える）で分けます。
- **押せる範囲**：図のボタンは、見た目が36〜54pt です。⑥ の行のボタン（36pt）と②の横並びのボタン（40pt）は、押せる範囲を44pt にします。
- **伏せられない人**：「読み始める」が同じ重みの主操作です。伏せる道は近道で、設定で切れます（PRD 12、AC-51）。

## 性格語が出ている所
- 静か：毎晩の道（③〜⑤）にほかの機能を出さない。数のバッジ、連続日数、祝う絵がない。
- 確か：理由は事実1行。奥付はデータのない行を出さない。「写真は保存しません」「本の文と写真は載りません」と書く。
- まっすぐ：画面ごとに主操作が1つ。ボタンの言葉は動作そのまま（読み始める、カードを送る）。
- 手で感じる：伏せて始める。自分の本の一行が、明朝の縦書きで出る。

## Takuma に見てほしい点
1. ロック画面の一行の大きさ（①）。実際の大きさだと、17pt で4字ずつ5列になります。読む気になる大きさか。
2. しおりの画面（②）の、主操作のほかの2つのボタン（どこまで読んだかを入れる、読み終えた）。毎晩の画面に出しておくか、ツールバーのメニューに入れるか。メニューにすると画面は静かになりますが、「読み終えた」が見つけにくくなります。
3. 読み終えのカード（⑧）に、アプリの名前を入れるか。
4. 次の1冊（⑥）に、本棚にない本が1冊だけ入る形。
5. 読み終えた画面を1つのスクロール（奥付 → 次の1冊 → カード）にしたこと。読み終えた余韻の画面と、次を選ぶ画面を分けたいなら、PRD の AC-78〜AC-81 の When に1タップ足すことになります（G0 の承認の前に指揮役へ）。
