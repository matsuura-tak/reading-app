## 2. 見せ方の判断
- **公平にするため、そろえたもの**
  - 長さ（10秒）、最後の溶け方、くり返し
  - 舞台の大きさ（幅いっぱい、縦横 4:5）と色
  - 手、iPhone、本の描き方（平らな形だけ。影、グラデーション、光はなし）
  - 色：本の色だけ。アプリの部品は黒、白、灰（前回の案「色は利用者の本から」、B-5）
  - 画面の要の文字の大きさ：舞台の幅の約3.8〜4.5%（幅390pxの画面で約13〜17px）
  - 各案の下：見出し2行（番号なし。1行目がきっかけ、2行目が画面に出るもの）、説明2行（幅320px以上で2行に入る長さ）、「もう一度再生」
  - 動きの拍の数：どれも3〜4拍（始まり、要の瞬間、体の動き、終わりの1枚）
- **見出しと説明のそろえ方（4. の 8 への手当て）**
  - 見出しは3つとも「〈きっかけ〉と、／〈画面に出るもの〉」の型です。比喩を使わず、見る人がする1つの動き（手に取る、向ける、開く）と、そのとき画面に出る物（一行、線、ページ）だけを書きました。
  - 長さは、全角に直して15.5〜18.5字です（半角は0.5字と数える）。読点のあとで改行し（`<br>`）、どの幅でも2行にしました。幅390pxでは見出しの右に「もう一度再生」が来て、320pxでは見出しの下に来ます（3つとも同じ）。
  - 盾、守る、止める のような比喩や強い動詞は使っていません。呼び名も見出しに使っていません。ただし案1の「続きの一行」は呼び名と同じ言葉です。比喩ではなく、画面に出る物そのものなので残しました。
  - 説明の2行も、3つとも「〈いつ〉、〈どの画面〉に、〈何が出る〉。〈そのあと人がすること〉。」の型にしました。前は案2だけが「いつ、何をする。画面の結果。」の型で、そのあとの動き（本を抜く）がありませんでした。見出しと同じ言葉をくり返さないよう、説明は「いつ」「どの画面か」「そのあと」を受け持ちます。長さは全角に直して32〜36.5字です。
  - 舞台の読み上げ（aria-label）の頭にあった呼び名（「夜の盾の場面。」など）も外しました。読み上げでも、名前の強さの差が出ないようにするためです。
- **見せる順番（4. の 3 への手当て）**
  - 場所と形：問いの下、ページのいちばん下に、小さな灰色の文字で「見せる順番」と、1〜6 の数字のボタンを置きました。押せる所は 44×44px です。数字の灰は、下の「補足の灰」と同じ色です。
  - いまの番号は、太字と丸い枠で示します（色だけに頼りません）。枠は #8E8E93 で、白の上で約3.3:1、黒の上で約6.4:1 です。
  - 読み上げ：「見せる順番」という名前のグループの中の、6つのボタンです。いまの番号は、押された状態（aria-pressed）として読まれます。
  - 番号を押すと、次の3つが起きます。
    1. 3つの案の並びが変わる。ページの中の順番そのものを入れ替えるので、読み上げの順も変わる
    2. ページのいちばん上に戻る
    3. 3つの舞台が、まだ再生していない状態（0秒で止まった形）に戻る。そのあとは、いまの決まりどおり、半分以上見えたら0秒から動く
  - 初めて開いたときは 1 です。最後に押した番号は、そのブラウザーに覚えておきます（localStorage）。読み書きは try/catch で包み、覚えておけない環境では毎回 1 で開きます。JS が動かないときは「見せる順番」は出ず、並びは 1 のままです。
  - 確かめ用に ?order=1〜6 も読みます（覚えた番号より先に使い、覚えはしません）。ページの中の操作だけで選べるので、これには頼りません。
  - 6通りの並びは次の表のとおりです。1 は前と同じ並びです。

| 番号 | 1番目 | 2番目 | 3番目 |
|---|---|---|---|
| 1 | 続きの一行 | 積読カメラ | 夜の盾 |
| 2 | 積読カメラ | 夜の盾 | 続きの一行 |
| 3 | 夜の盾 | 続きの一行 | 積読カメラ |
| 4 | 続きの一行 | 夜の盾 | 積読カメラ |
| 5 | 夜の盾 | 積読カメラ | 続きの一行 |
| 6 | 積読カメラ | 続きの一行 | 夜の盾 |

- 6つを1人に1つずつ使うと、どの案も1番目、2番目、3番目に2回ずつ来ます。ある案のすぐ後に別の案が来る組（たとえば、続きの一行のすぐ後に積読カメラ）も、6つの組が2回ずつです。1〜3 だけ、または 4〜6 だけを使っても、どの案も各位置に1回ずつ来ます（人数がそろわなかったとき用）。
- 使い方（Takuma へ）：見せる前に、いちばん下の「見せる順番」で、その人の番号を押します。ページが上に戻るので、そのまま渡します。1人に1つの番号を使い、同じ番号を2人に使わないでください。答えと一緒に、何番で見せたかをメモしてください。Takuma 自身の答えは、すでに 1 の並びで見ているなら 1 として数え、残りの5人に 2〜6 を使うのをおすすめします。
- **前回の条件との対応**
  - G-2：光らせない。案2は細い線1本と1行だけ
  - G-3：「AI」の語は使わない。案2の画面は「次は、これ。」と、確かめられる事実（p.1、約15分）だけ
  - 点数、星、連続日数はない。矢印は、指示の文言にある「p.43 → p.61」の1つだけ
  - 1-3 の形：音なしで伝わる、前と後が同じ画面の中で変わる、画面の文字は1〜2行、映るのは手と本と iPhone だけ、最初の3秒で場面がわかる、最後の1枚で中身がわかる
  - App Store の版（手を映さない版）は作っていない（今回の目的の外）
- **文言と絵**
  - 案1の一行「雨は、まだやまなかった。」は designer が作った文です。引用ではありません。
  - 本の題（白い港、冬の庭、小さな舟、川のほとり、午後の地図、遠い灯、石の記憶）も作った題です。同じ題の本が実在するかは調べていません。
  - 「SNS」のアイコンは、実在のアプリをまねず、灰の角丸に吹き出しの形と「SNS」の文字にしました。
  - 縦書きは HTML の writing-mode: vertical-rl で組みました（句読点が縦書き用の位置に出るため）。「124」「10」は縦中横です。
- **動きを減らす設定のとき**
  - 動かさずに、同じ舞台をその時刻で止めた3コマを縦に並べ、「1 / 3」などの番号を添えます。「もう一度再生」は出しません（動くものがないため）。
  - 3コマの時刻：案1は 3.0、5.9、8.6秒。案2は 2.2、4.5、8.6秒。案3は 1.35、3.5、8.6秒。
- **再生**
  - 舞台が半分以上見えたら、0秒から始めます。全部見えなくなったら止め、戻ると続きから動きます。「もう一度再生」は0秒からやり直します。
  - JS が動かない、または IntersectionObserver がない環境では、最初から全部動かします。
  - 見せる順番の番号を押すと、3つとも、まだ再生していない状態に戻し、見え方を数え直します（IntersectionObserver から一度外して付け直す）。IntersectionObserver がない環境では、3つとも0秒から動かし直します。
- **色のトークン**
  - :root に置きました。ダークの値は、@media (prefers-color-scheme: dark) の :root:not([data-theme="light"]) と、:root[data-theme="dark"] の2か所に同じ値を書きました。body に背景色を指定しました。
  - コントラスト（designer の手計算、概算）
    - 本文 #1C1C1E と白：約17:1
    - 補足の灰 #6E6E73 と白：約5.1:1。ダークの #98989F と黒：約7.3:1
    - ボタンの枠 #8E8E93：白の上で約3.3:1、黒の上で約6.4:1
    - ロック画面の文字 #F2F2F7 と #141416：約16:1
    - 紙の画面の文字 #1C1C1E と #F6F3EC：約15:1（ダークの紙 #E7E2D6 で約13:1）
    - カメラ画面の白い文字と #2B2A28：約14:1

    - 手の色と舞台：ライト約3.1:1、ダーク約3.3:1
- **読み上げ**：各舞台は role="img" で、場面を言葉にした aria-label を付けました。3コマにはコマごとのラベルがあります。「もう一度再生」は aria-describedby で見出しにつなぎました。
- **確かめ用の口**：URL に ?t=秒 を付けると、その時刻で止まります。?theme=dark か ?theme=light で配色を固定します。?order=1〜6 で見せる順番を選びます。Artifact で見る人には関係ありません（付けなければ何も起きません）。

  - まず --dump-dom（仮想時間）で流しました。並べ替え、上に戻ること、番号を覚えることは確かめられましたが、舞台が見えたときの再生は、仮想時間では描画が進まないため、ほとんど起きませんでした（試験の環境の限界）。
  - そこで、Chrome（ヘッドレス）を DevTools の口で動かす小さな Python（scripts/cdp_run.py。標準ライブラリだけ）で、実際の時間で同じ試験を流しました（約20秒）。結果は次のとおりです。
    - 6つの番号を順に押すと、並びは 1=123、2=231、3=312、4=132、5=321、6=213（数字は案の印）。どの案も1番目、2番目、3番目に2回ずつ。すぐ後に来る組も、6つの組が2回ずつ。

## 4. 弱い所
1. **絵の量が同じではありません。** 案2は色の付いた背表紙が7冊あり、いちばん色が多く、にぎやかに見えます。案1と案3は同じ机と同じ本なので、似て見え、印象が混ざるおそれがあります。
2. **視点が違います。** 案1と案3は上から、案2は前から見ています（カメラの画面を見せるため）。
3. **順番の効果があります。** 並びは 1→2→3 で固定です。最後に見たものが記憶に残りやすくなります。人によって見る順を変えるか、3つとも見終わってから答えてもらうのがよいと見ます［推測］。
   - 直したこと（2026-10-16）：見せる順番を6通りから選べるようにした。6人に1つずつ使えば、どの案も各位置に2回ずつ来て、順番の効果が3つに同じだけかかる（2. の「見せる順番」）。
4. **技術で確かめていない形を見せています。**
   - 案1：ロック画面に、決めた時刻に縦書きの一行を出せるか
   - 案2：縦書きの背表紙を読めるか（確かめ1）
   - 案3：盾の画面を文庫の姿にできるか（Screen Time の盾の制約）
   - 3つとも、うまくいった場合だけを見せています。読み違い、「確かめてください」、許可を断られたときの場面は入れていません。動画が良く見えても、作れるとは限りません。
5. **手の形が粗いです。** ミトンのような形です。手に見えるかは、designer が静止画を見て判断しただけです。
6. **小さい画面では、文字が小さくなります。** 幅320pxでは、背表紙の題が約7.5px、案3の「SNS」が約7pxです。
7. **案1の「18分後」は、絵だけで伝えています。** 暗転、時計の変化（23:40 → 23:58）、「18分」の3つです。説明の文には書いていないので、伝わるかは見る人しだいです。
8. **名前の強さが違います。** 「夜の盾」は、名前だけで印象が強いかもしれません。見出しの言葉が選ばれ方に影響するおそれがあります。
   - 直したこと（2026-10-16）：見出しの番号と比喩を外し、3つとも「〈きっかけ〉と、〈画面に出るもの〉」の同じ型と長さにした（1. のはじめの表）。ただ「SNS」のように、中身の言葉そのものが持つ強さの差は残る。
9. **英語版はありません。** 見る人は日本語を話す人だと想定しました。
10. **舞台の中の文字は、端末の文字の大きさの設定では大きくなりません。** 見出し、説明、問いは、Safari では文字の大きさの設定に従います（-apple-system-body）。

## 5. 指揮役へのお願い（Takuma に、公開のページで確かめてもらう）
Takuma が自分の iPhone で、公開している Artifact のページを開き、次を確かめてもらってください。手元で確かめたのはヘッドレスの Chrome だけで、Artifact の中と実機は見ていません（3.）。
1. 開くと、見出しが上から「iPhone を手に取ると、」「カメラを向けると、」「SNS を開くと、」の順か。見出しに番号がないか
2. いちばん上の舞台が、見えたときに自動で動き始めるか
3. いちばん下までスクロールし、「見せる順番」の 5 を押す。ページのいちばん上に戻るか。見出しが「SNS を開くと、」「カメラを向けると、」「iPhone を手に取ると、」の順に変わるか。5 に丸い枠が付いているか
4. 上に戻ったあと、1つ目の舞台（ホーム画面の場面）が最初から動き始めるか。下へ送ると、2つ目と3つ目も、半分以上見えたところで最初から動くか
5. ページを閉じて開き直すと、5 の並びのままか。1 に戻っていても使えます（番号を覚えておけない環境です）。そのときは、毎回、番号を押してから渡してください
6. 「もう一度再生」で、その舞台が最初に戻るか
7. 動きを減らす設定（設定 → アクセシビリティ → 動作 → 視差効果を減らす）で、3案とも3コマになるか。番号を押すと、3コマのまま並びが変わるか
- 3. で上に戻らないときも、渡す前に指でいちばん上まで戻せば使えます。そのことを designer に戻してください。ほかにうまくいかない所があれば、どの番号で何が起きたかを designer に戻してください。
- 確かめが終わったら、最初の人に見せる前に、その人の番号を押してください（2. の「見せる順番」の使い方）。
