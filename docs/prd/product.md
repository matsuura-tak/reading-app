## 1. 対象の層
- 中心：日本に住み、紙の本を読みたいのに、平日の夜はスマホに流れて読めずに終わる、働いている人。
  - 16歳以上の62.6%が1か月に1冊も読まず、69.1%が読書量が「減っている」と答えた。減った理由の1位は「情報機器（携帯電話、スマートフォン、タブレット、パソコン、ゲーム機等）で時間が取られる」43.6%［公開情報 https://www.nippon.com/ja/japan-data/h02135/ 文化庁「国語に関する世論調査」令和5年度、回答3,559人。選択肢の原文は文化庁の PDF で、G0 r1 の tech-lead その2 の 8 が確かめた］。夜と SNS に読み替えるのは［推測］。
  - 2位は「仕事や勉強が忙しくて読む時間がない」38.9%で、20〜40代では6割台［公開情報 https://www.bunka.go.jp/koho_hodo_oshirase/hodohappyo/pdf/94111701_02.pdf 。docs/reviews/001-reading-session-reselect-pdm-core.md の 1-2 で読んだ値］。
  - 静かに読むための mekuru が、公開（2026-08-12）から約2か月で評価370件、平均4.69を集めた［公開情報 https://apps.apple.com/jp/app/id6792955764 、2026-10-18］。
- 次の層：積読があり、1冊を読み終えたあと、次の本がなかなか決まらない人［推測。001 の確かめ 3b で確かめる］。書店の購入者の79%に積読がある［公開情報 https://prtimes.jp/main/html/rd/p/000000012.000027516.html 丸善ジュンク堂 2019、N=2,104。よく読む人に偏る］。
- 対象にしない層：蔵書をすべて登録して管理したい人、感想を公開して人と交流したい人、読書の SNS が目的の人。ブクログ（評価28,261件）、読書メーター（7,190件）、Goodreads（US 758,792件）が、人の数とデータで強い［公開情報 4 の表の URL］。
- 本の管理の線：このアプリが持つのは「今の1冊、積読、読み終えた本」の3つの置き場所だけ。並べ替えの種類、タグ、評価、感想、蔵書の統計は持たない。
- 人に見せる線：人に見せるのは、利用者が自分で送る「読み終えのカード」（画像）だけ。アプリの中に公開の面（タイムライン、プロフィール、いいね、コメント、フォロー、順位）を持たない。

## 2. 中心の Job
- 仕事のあとの夜、手がスマホに伸びかけたとき、考えずに本の続きに戻りたい。そうすれば、読みたいのに読めずに終わる夜が減る。
  - 「続き」には、1冊を読み終えた次の夜の「次の本のはじめ」も入る。次の本が決まらないと、翌晩の戻り先がなくなるため［推測。確かめ 3b で確かめる］。
- 機能の面：今夜どの本のどこから読むかが、探さずにわかり、読んだ時間とページが残る。
- 気持ちの面：スマホに流された後ろめたさから離れ、少しでも本に戻れたと思える［推測］。
- 人の目の面：「本を読む人」でいる自分を自分で確かめられ、読み終えたことを、送りたい相手にだけ伝えられる［推測］。

## 5. 位置づけ（1文）
夜、iPhone を手に取るとロック画面に自分の紙の本の昨夜の一行が縦書きで出て、伏せるとその本の読書が始まり、1冊を読み終えた夜にだけ奥付（出版社、受賞）と積読からの次の1冊が出る読書アプリで、時間を数える読書タイマー（ToRead、Bookmory）とも、本の管理と読書の SNS（ブクログ、読書メーター、Goodreads）とも違う。

- 守ること
  - 毎晩の道（ロック画面の一行 → 開く → 伏せるか「読み始める」→ 終える → しおりを挟む）に、ほかの機能を足さない。登録、出版社、受賞、次の1冊は、本を加えたときと読み終えた夜にだけ出す。
  - 美しさのために手順も待ちも増やさない（4 の Forest の不満）。
  - 伏せられない人のために、「読み始める」ボタンを伏せる道と同じ重みで残す。
  - アプリの中に公開の面を持たない（1 の人に見せる線）。友人の機能を足すときも、フィード、自由な文、通知、数の比べ合いを持たない（docs/reviews/001-reading-session-integrate-proposal.md の 1）。
  - 他人のデータがないうちは「これを読んだ人は」という名前を使わない。
  - 無料のものを、後から有料にしない。芯（毎晩の入口と本の出口）は無料のまま（Takuma の決定）。
  - 購入の案内は、利用者が自分で開いたときだけ出す。毎晩の道と読み終えた夜の流れには出さない（Takuma の決定）。
  - AI に本の中身の文を作らせない（v1。裁定 12）。OS の機能そのもの（端末の辞書の画面など）に値段を付けない（審査ガイドライン 4.10。裁定 13）。
- 注意
  - 部品にはどれも先行がある（伏せるタイマー、ロック画面の表示、連続スキャン、受賞の一覧、おすすめ）。新しいのは、毎晩の入口と本の出口をつないだ輪と、ロック画面の縦書きの一行［推測］。
  - 実際のロック画面では、一行は時計の下の小さな枠（長方形のウィジェット 172×76 pt。いちばん小さい機種で 153×68 pt。15〜25字の句が収まりのよい長さ）に出る。10秒の試作のように画面いっぱいには出ない。大きく出るのは、充電中の StandBy［公開情報 https://developer.apple.com/design/human-interface-guidelines/widgets 。docs/reviews/001-reading-session-integrate-tech-lead.md の 5］。ストアの文とスクリーンショットも、この大きさに合わせる（審査ガイドライン 2.3）。

## 6. North Star と入力指標
- 言葉の決まり：「晩」は、読み始めの時刻を、読み始めたときのタイムゾーンで表し、4:00 より前なら前の日とした日付（例：2026-10-16 00:40 に読み始めたら 10/15 の晩）。「週」は月曜〜日曜（晩の日付で数える）。
- North Star：**週に2晩以上読んだ人の数**＝その週に、その晩の読書の合計が10分以上の晩が2晩以上ある人の数。
  - 理由：Job は「読めずに終わる夜を減らす」ことで、利用者が受け取る価値は読めた晩の数に表れる。前の版の「週の合計15分以上」は、日曜に1回読んだだけでも数えてしまう［推測］。ダウンロード数や起動数では読んだかどうかがわからない。
  - 2晩と10分の線は［推測］。外部の計測を入れた版の公開後14日のデータで見直す案を Takuma に出す。
  - v1.0 では測れない（下の測り方）。v1.0 は App Store Connect の Day 7 継続率を、North Star の代わりに見る（001 の 13）。
- 入力指標（チームが日々の仕事で直接動かせるもの）
  - I-1 最初の読書の到達率：初めて開いた人のうち、24時間以内に1分以上の読書を1回残した人の割合。（登録の速さと確かさで動く。v1.0 は Day 1 継続率で代える）
  - I-2 入口から始まった読書の割合：残った読書（1分以上）のうち、続きの一行（ロック画面のウィジェット、小のウィジェット、Live Activity）を押して開き、そのまま始まった読書の割合。（一行の見せ方、ウィジェットの置き方の案内で動く。ロック画面で一行が見られたかは測る API がない見込みなので、押して開いたことで代える［推測。tech-lead の G0 r1 その1 の答え］）
  - I-3 本から本への継続率：1冊を読み終えた人のうち、7日以内に次の本の読書を1回以上残した人の割合。（奥付、次の1冊、登録で動く）
  - I-4 一行の更新率：残った読書のうち、そのあと一行を新しくした（撮るか手で入れた）回の割合（読まずに挟んだしおりは数えない）。（撮る道の速さ、読み取りの確かさで動く。一行が古いか空の夜が続くと、ロック画面は書名とページだけになり、ほかのアプリと同じになるため）
- ガードレール
  - G-1 1晩にアプリを前に出していた時間の中央値（読んでいる時間を除く）：30秒以内［推測］。（4つを足しても、スマホの時間を増やさない線。designer の 7-1、integrate-pdm の 4-2。v1.0 は G3 で design-reviewer が録画で見る）
  - G-2 クラッシュ率（App Store Connect の Crash Rate＝クラッシュ数÷セッション数。分析の共有に同意した人の分だけ）：0.5%以下［推測］［公開情報 https://developer.apple.com/help/app-store-connect-analytics/benchmarks/peer-group-benchmarks/ ］。
- 事業性の指標（主にしない）：Day 35 Download to Paid Conversion（"The percentage of first-time downloads or redownloads that were followed by an In-App Purchase within 35 days of download."［公開情報 上の URL、2026-10-18 に WebFetch］）と、課金を入れた版の公開から90日の手取り。線は 001 の 13 と 14。
- 基準値：すべて未計測（公開後14日で測る）。同業比較は App Store Connect の Day 1、7、28 の継続率とクラッシュ率を参考に見る（上の URL。分析の共有に同意した人だけで、雑音が加わり、群が小さいと出ない）。
- 測り方（決まった。裁定 10）
  - v1.0 は App Store Connect の App Analytics だけ：継続率、セッション、クラッシュ率、売上がわかる（分析の共有に同意した人の分）。イベントは送らない。North Star、I-1〜I-4、G-1 は測れないので、Day 7 継続率と Day 1 継続率で代え、G-1 は G3 の録画で見る（001 の 13）。
  - 外部の計測サービスに匿名の値を送る形は v1.1 以降。審査ガイドライン 5.1.1(ii) の同意と取り消しが要り（tech-lead の G0 r1 その1 の指摘4）、指標は同意した人の中の値になる。そのときに North Star と I-2〜I-4 を測り、線はその版の PRD で公開の前に決める。
  - 利用者が自分で送る形は、少なく偏るので使わない［推測］。
