# 第1部 発見（何を、なぜ作るか）

## 1. 紹介文
「よむま（仮の名前）」は、スマホに時間を取られて本から遠ざかった人のための、読書の時間のアプリです。本を開く前に iPhone を伏せて置くと、ボタンを押さずに、一覧のいちばん上の本（最後に読んだか加えた本）の読書が始まります。起こしても、ロックしても、ほかのアプリを開いても、「終える」を押すまで時間は数え続け、終えると「どの本を何分読んだか」がその場で残ります。「読む」を押してからスマホを置く読書タイマーより、アプリを開いてから読み始めるまでの動作が2つから1つに減り、ストップウォッチとメモより、毎回書き写す約15字が0字になります。伏せられないときは「読む」でも同じように始められ、アカウントも通信も要らず、読んだ本の名前は端末の外に出ません。

- 数字の根拠：「2つから1つ」は、ToRead の「読書セッションを開始し、スマホを置いて、ただ読む」［公開情報 E-7］と、5 で決めた振る舞いを比べた数え［推測］。「約15字」はストップウォッチとメモの手順を数えた見積もり［推測］。「数え続ける」は AC-10、「外に出ない」は 12 で確かめる。
- ToRead との差：伏せて始める道は ToRead にない［公開情報 E-14］。読書中に押せるものは4つから1つになる［公開情報 E-12］。ただし ToRead もショートカットや背面タップでボタンを押さずに始められ［公開情報 E-14］、動作が1つ減ることの価値は確かめていない（6 の価値）。
- 伏せて始めるアプリとの差：伏せて始める集中タイマーは2018年からあり［公開情報 E-13］、US には伏せて始める読書アプリ Offshelf もある（JP のストアにはない）［公開情報 E-16］。説明文を見たうち6本は、持ち上げると止まるか、一時停止するか、終わる［公開情報 E-13、E-16］。こちらは起こしても止めずに「終える」まで数え、本ごとに残す。

## 2. 中心の Job
- Job ストーリー（1つだけ）：本を読もうと腰を下ろしたとき、その本と過ごした時間を、手を止めずにまるごと残したい。そうすれば、読書が暮らしに戻ってきたと実感でき、また本を開きたくなる。
- 機能の面：読み始めから終わりまでの時間が、途中で途切れずに本ごとに残る。　気持ちの面：スマホに引っ張られず、落ち着いて本に向き合える［推測］。　人の目の面：「本を読む人」でいる自分を、自分で確かめられる［推測］。

- いちばん近い3件と、伏せて始めるアプリとの違い（審査ガイドライン 4.3(b) のため。いちばん近い競合は ToRead にそろえる）：

## 5. 機会と解決
- 根（成果）：I-1 最初の読書の到達率（初めて開いた人のうち、24時間以内に1分以上の読書を1回残した人の割合）
- 機会（顧客の不満を短く言い直した。原文の引用は E-n にある。どれも解き方が2つ以上ある）：
  - O-1 読んでいる途中で数えるのが止まり、読んだ時間が消える［公開情報 E-3］（解き方：数え続ける、後から手で直す）
  - O-2 本を登録するまでの入力や質問が多くて、読む前に疲れる［公開情報 E-4］（解き方：タイトルだけで加える、バーコード、検索）
  - O-3 スマホを手に取ると、SNS やほかのことに引っ張られて、読み始められないか、読書がそこで終わる。E-1 で言えるのは「携帯電話、スマートフォンなどで時間が取られる」まで。SNS とほかのことは mekuru のレビューの声［公開情報 E-1、E-10］（解き方：押せるものが1つの画面、伏せて始める、ほかのアプリを止める）
  - O-4 読み終えても何も残らず、読めたのか実感がない［推測］（解き方：終わりに分数を出す、本ごとの合計、記録の一覧）
- 選んだ機会と理由：違いを生む機会は O-3。読書量が減った理由の1位がスマホで［公開情報 E-1］、ToRead はスマホを置くことを利用者に頼むだけで、置く動作を始まりにはしていない［公開情報 E-14］。O-1 は ToRead などがすでに解いた当たり前の品質だが［公開情報 E-7、E-8］、mekuru の不満［公開情報 E-3］どおり外せない。O-2 と O-4 は 9 の当たり前と性能の項目で受ける。

- S-6 の振る舞いで pdm が決めたこと（形は G1 で designer が、実現性は tech-lead が確かめる。AC は 11 の AC-26〜AC-33）：
  - どの本で始まるか：一覧のいちばん上の本（最後に読んだか加えた本。AC-4 の並び）。選ぶ操作は足さない。伏せるときは画面を見ないので、どの本か迷わない1つの決まりにする。ほかの本は「読む」で始める。審査の担当は、本を1冊加えて伏せるだけで確かめられる（17）。
  - 伏せて始まる場所：一覧の画面がアプリの前面にあり、画面が点いていて、読んでいない（idle）ときだけ。本が0冊なら何も起きない。本の追加と編集、記録の一覧、終わりの画面、確認の画面では始めない。
  - 始まるまでと、始まったあと：伏せて置いてから2秒以内に始まる。誤って始まるのを防ぐ待ちは、この2秒の中で tech-lead の案の1.0秒にする（12）。始まったら iOS で鳴る触覚1回と VoiceOver の読み上げ1回（designer の案。触覚の種類は G1 で designer が決める）。起こしても、持ち上げても、ロックしても止めず、終えるのは「終える」だけ（S-3 を捨てた理由）。
  - 終わりの画面で伏せ直しても、続きは始めない（v1）。2週の枠では伏せて始まる場所を一覧の1つに絞る。読み終えてスマホを伏せて置く動作と区別できず、終え忘れ（7 の1）を増やすおそれがある［推測］。続けるときは「閉じる」で一覧に戻って伏せれば、いま読んだ本（いちばん上）で始まり、操作は1回増えるだけ。
  - 「読む」ボタンを残し、伏せられない人に配慮する：伏せる道と同じ重みで残し、どの本も「読む」で始められる（形は designer が決める）。どちらから始めても、読書中の画面と記録は同じ。手や姿勢の事情、スタンドに置く人［公開情報 E-15］、立って読む人、VoiceOver の人は、「読む」で同じ体験になる（HIG の「Consider a variety of input methods」［公開情報 design/001-reading-session-research.md の R-12］）。伏せて始めたときは書名を読み上げ、触覚を切っている人も、起こせば読書中の画面で始まったとわかる。伏せる道を切る設定は v1 に入れる（既定はオン。プライバシーポリシーへのリンクと同じ設定の画面に置く。11 の AC-33）。WCAG 2.5.4（Level A）は、動きで動く機能に、画面の部品で同じことができることと、動きへの反応を切れることの両方を求める。「読む」で同じことができる以上、例外の「Essential」に当たらない［公開情報 https://www.w3.org/WAI/WCAG22/Understanding/motion-actuation.html］。誤って始まる多さは 13 で見る。

## 8. 推奨
- 作る / 作らない / 形を変える：形を変える。案 A「伏せて読み始める」を中心にした形で、2週の枠で作る。18 の Q9 は (a) に決まった（2026-10-16）。G0 の承認は、Takuma の ToRead のメモと比べ直し、実機の確かめ①〜③の結果を見てからを推す。理由は4つ。
  - ToRead にない違いが1つできる。ToRead の始め方は「ワンタップ」と、ショートカットや背面タップで、製品ページに「伏せ」の語はない［公開情報 E-14］。
  - Q8 の線を満たす。違いを審査メモの1文で書け、審査の担当が約30秒で、伏せると読書が始まることを確かめられる（17。記録が残るところまでは含めない、という指揮役の裁定に従う）。
  - 伏せて始めるアプリとも体験が違う。説明文を見たうち6本は持ち上げると止まるか終わる［公開情報 E-13、E-16］。こちらは起こしても止めずに数え、本ごとに残し、統計や共有や順位を持たない（5、10）。
  - 手順も待ちも増やさない。「読む」を押してから置く2つの動作が1つになり、演出の待ちは0秒（designer の案）［推測］。
- 考えを変える条件：(1) Takuma のメモに読み始めのほかの強い不満が出たら、違いを入れ替える（Q8 の追加の決定）。読み始めの不満もほかの強い不満もなければ、ToRead で足りているとみて「作らない」に戻すことを推す。(2) 実機の確かめ①〜③で、許可のダイアログなしでは伏せた向きを取れない（縦の固定がオンだと届かず、代わりの取り方に許可が要る場合を含む）か、誤って始まるのを防げないとわかったら、案 A をやめ、「作らない」か designer の次点に戻すことを Takuma に推す。(3) G5 より前に ToRead が伏せて始める道を足すか、Offshelf が JP に出たら、17 の審査メモの違いを書き直す。
- いちばん強い反論：伏せて始めることは新しくない。集中タイマーでは FLIP（2018年、JP 790件）とベアフォーカスタイマー（2018年、JP 119件）からあり、伏せて使うものは 2026-06-08 より後も JP で4本出た［公開情報 E-13］。読書でも、US の Offshelf が「Place your phone face-down to start a session」を 2026-02-25 から持つ［公開情報 E-16］。審査の担当が店全体で見れば、伏せて始める読書タイマーは "meaningfully different" に見えないかもしれない［推測］。ToRead もショートカットや背面タップでボタンを押さずに始められ［公開情報 E-14］、伏せる道を足すのも難しくない［推測］。そのうえ、伏せて始める価値はだれにも確かめておらず、「fun gimmick」「needlessly difficult to use」という声もある［公開情報 E-15］。
- 作らない場合に起きること：利用者は今までどおり、ToRead、伏せるタイマー、ストップウォッチ、または何もしないで読む［推測］。読む時間を残したい人には、無料で広告のない選択肢がすでにある［公開情報 E-6、E-7］。このアプリは中心の機能を持たないまま、Q8 (a) の「アプリの中心から見直す」に戻り、product.md の 5 も決められない。本棚や統計から作ると、評価28,250件のブクログなどと同じ土俵に立つ［公開情報 product.md の 4］。

## 10. やらないこと（非目標）と、はまりやすい所
- やらないこと（理由を1行ずつ）：
  - ISBN、バーコード、タイトル検索、表紙の画像：Q1 で決まるまで入れない。カメラの許可と外部への通信が要り、オフラインで動かなくなる。検索と読み取りの失敗が競合の不満に出ている［公開情報 3 の表、product.md の 4］。
  - 本棚の分類（読みたい、読んだ）、評価、感想、引用のメモ：時間を残す Job に直接効かない。本の管理はブクログ（評価28,250件［公開情報 docs/prd/product.md の 4］）が強い。
  - 統計、グラフ、目標、連続日数、リマインドの通知、共有カード：数字で急かすと穏やかに読む体験に逆らう［推測］。Offshelf は統計と共有カードを持つ［公開情報 E-16］が、こちらは持たないことを違いにする。I-3 を見てから決める。
  - ロック画面と Dynamic Island の表示：時間の枠に入らない。次の機能の候補。
  - 一時停止：終えてもう一度始めれば、同じ本の合計に足される。
  - 自動で終える：mekuru の「2時間しか記録されていなかった」の不満［公開情報 E-3］。終え忘れは、記録を直すこと（AC-19）と1440分の上限（AC-34）で受ける。
  - 起こしたとき、持ち上げたときに一時停止するか終える：画面に触れないことも、スマホを手に取ることも、読書の終わりの証拠にならない（5 の S-3）。伏せるタイマーに「理由なく止まる」不満がある［公開情報 E-15］。
  - 終わりの画面で伏せ直すと続きを始める：読み終えてスマホを伏せて置く癖と区別できず、終え忘れを増やす（5 の S-6、docs/reviews/001-reading-session-G0-tech-lead-flip-research.md の 3 の S5）。続けるときは「閉じる」で一覧に戻って伏せる。
  - 伏せて始める本を選ぶ操作：伏せるときは画面を見ないので、いちばん上の本の1つの決まりにする（5 の S-6）。ほかの本は「読む」で始める。
  - 静止を確かめて持ち上げた状態と区別する（Core Motion）：許可のダイアログが要るかが文書で決まらず、シミュレーターで試せない（tech-lead の調べもの 1 と 3 の O7）。G4-9 の結果で見直す。
  - 近接センサーで伏せた画面を消す：近接センサーのない機種があり、消えている間に自動ロックが進むかもわからない（tech-lead の調べもの 2）。
  - 環境音：「競合にあるから」以上の理由がない。音源の権利の確認も要る。
  - 一緒に読む、共有、SNS：mekuru の領域。v1 は一人の時間に絞る。
  - 集中モードの切り替えや、ほかのアプリのブロック：Forest の領域。新しい権限が要る［推測］。
  - iCloud の同期、課金、広告：Q3 と Q5 で決める。
  - iPad 専用の画面、Apple Watch、ウィジェット：時間の枠に入らない。iPhone 用の画面を iPad の互換表示で動かすことは止めない。Mac と Vision Pro に配るかは 18 の Q10。
- はまりやすい所と避け方：
  - 一覧のまま伏せて置いて誤って始まる（会議、食事、かばん）：伏せが1.0秒続いてから始め（AC-27）、始まったら触覚1回で気づけるようにする（AC-26）。1分未満は残らず（AC-15）、残った記録は消せる（AC-21）。何度も起きる人は伏せる道を切れる（AC-33）。多さは 13 と 14 の「伏せて始めて1分未満で終えた割合」で見る。
  - 仰向けに寝て一覧を見ながら iPhone を顔の上に持ち上げる：画面が下を向き、伏せた向きになりうる（UIDevice の向きは静止しているかを見ない。tech-lead の調べもの 1）。実機の確かめ③と G4-9 で多さを見て、静止の確かめを足すかを決める。
  - スタンドに置く人、硬い机に画面を当てたくない人［公開情報 E-15］：「読む」で同じ体験になる（AC-5、AC-9）。立てて置いても伏せた向きにならないので、何も起きない。
  - 伏せたあとの消灯：画面は自動ロックの時間（30秒〜5分。「なし」の人は消えない）まで点いたままになる。画面を点けたままにする設定は使わない（AC-12）。Apple も "Most apps should let the system turn off the screen when the idle timer elapses." と書く［公開情報 https://developer.apple.com/documentation/uikit/uiapplication/isidletimerdisabled ］。読書中の画面の地の色は designer が決める。
  - iPad の互換表示：伏せた向きはシミュレーターで届いた（tech-lead の spike）が、触覚は出ない見込み（HIG は触覚を "on supported iPhone models" と書く［公開情報 https://developer.apple.com/design/human-interface-guidelines/playing-haptics ］）。始まったことは読み上げと読書中の画面で伝わる。
  - Mac と Vision Pro：伏せる道が効かない（tech-lead の調べもの 6）。配るなら案内を出さず（AC-33 の (2)）、「読む」で使う（18 の Q10）。
  - 触覚の種類：SwiftUI の SensoryFeedback の .start と .stop は "Only plays feedback on watchOS." で、iPhone では鳴らない［公開情報 https://developer.apple.com/documentation/swiftui/sensoryfeedback/start ］。iOS で鳴る種類を designer が G1 で決め、始まりと終わりで同じ触覚にしない。
  - 実機の確かめ①〜③（18。G0 r2 の前に Takuma が行う）の結果で変わること。第2部は、UIDevice の伏せた向き（faceDown）を許可なしで取れる前提で書いた：
    - ① 縦の固定がオンだと伏せた向きが届かない：縦の固定を使う人には伏せる道が効かない。tech-lead が Core Motion に替えるかを決め、替えると許可が要るなら、8 の「考えを変える条件」(2) に当てて Takuma に上げる。替えないなら、案内の1行（AC-32）に縦の固定のことを書く（designer）。
    - ② 許可のダイアログが出る：AC-24 の0回が崩れるので、8 の (2) に当てる。それでも進めると決まったら、許可を断ったときの AC（伏せても始まらず、案内を出さず、「読む」で始められる）を足し、AC-24 を直す。
    - ③ 仰向けで持ち上げると伏せた向きになる：上の「仰向け」の行のとおり、G4-9 で多さを見る。
  - 日付やタイムゾーンをまたぐ読書：読み始めたときのタイムゾーンでの、読み始めの日付にする（AC-17）。
  - 端末の時刻を手で変えた：負の分は残さず（AC-35）、1440分を超える分は1440分で残す（AC-34）。時刻の取り方は docs/reviews/001-reading-session-G0-tech-lead-r1.md その1 の 1-b のとおり。
  - 美しさが手順と待ちを増やす（Forest の不満［公開情報 E-5］）：読み始めまで2回、終えるまで1回の操作（AC-5、AC-14）と、12 の秒数を線にする。
  - 「美しい」は AC で測れない：AC には数えられるもの（押せる要素の数、操作の数、秒数、ダイアログの数）だけを書き、見た目は G1 と G3 の design-reviewer の採点表で判定する。
  - 文言キーと識別子は仮の名前：designer が決めた名前は design/ の対応表を正とし、承認の後に PRD は直さない（11 の冒頭）。
  - 時間で消える知らせ：`session.tooShort` などを時間で消す形にするなら、出ている秒数を design/ に書く（テストが見る前に消えて結果が揺れないように）。

## 11. 受け入れ条件
読み方の決まり（すべての AC に効く）：
- 状態は `idle`（読んでいない）と `reading`（読書中）の2つ。`reading` のときは、アプリを前面にすると読書中の画面が出て、強制終了して開き直しても同じ本の読書中の画面に戻る。`idle` のときは読書中の画面が出ない。G3 では状態の名前を H9 で読む。
- 分数は、経過の秒を60で割って切り捨てた整数。記録が残るのは60秒以上（60秒ちょうどは1分）。
- 本の合計は、その本の記録の分数の和（秒の和からは求めない）。本の一覧の各行と終わりの画面に出る。
- 読み始めの時刻は、「読む」を受けた時刻か、伏せが1.0秒続いて始めると決めた時刻。記録の日付は、読み始めの時刻を、読み始めたときのタイムゾーンで表した日付。分は時刻の差で、タイムゾーンに左右されない。
- 字の数は、前後の空白を除いたあとの書記素（見た目の1字。Swift の Character）の数。空白は、半角スペース、全角スペース（U+3000）、タブ、改行。加えるときと直すときは、前後の空白を除いて保存し、除いた形で出す。
- 並びの日時は、その本に残っている記録のうち最も新しい読み始めの時刻。記録がなければ加えた時刻。同じ時刻なら、加えた時刻が新しい本を上にする。
- 押せる要素は、ボタン、リンク、セル、スイッチ、スライダー、ステッパー、入力欄、タブバー、ナビゲーションバーの数の合計。
- 「識別子 `x`」は accessibilityIdentifier、「文言キー `x`」は文の名前で、どちらも仮。designer が決めた名前は design/ の対応表を正とし、承認の後に PRD は直さない。「文言キー `x` が出る」は、その文を出す要素があり、文字が `x` の日本語（英語の構成では英語）と同じこと。分と日付の画面での書き方（60分以上を時間と分で出すかを含む）は design/ に従い、テストは AC の値をその書き方に直して比べる。
- 「アプリが出した触覚」と「アプリが出した読み上げ」は、アプリが出した回数で、H17 で読む。体に届いたか、聞こえたかは G4 で見る。
- 時計は H4（起動のときに固定する）と H5（起動したまま進める。アプリが後ろにいる間も）で置き換え、sleep で待たない。伏せの待ちの1.0秒も同じ時計で数える（H16）。
- つなぎ口の番号：H1〜H14 は docs/reviews/001-reading-session-G0-verifier-r1.md の証拠の 4、H15〜H18 は docs/reviews/001-reading-session-G0-tech-lead-flip-research.md の 4-3。伏せる道の設定の値を入れる H2 の拡張（`flipToStart`）も含め、形は tech-lead が G1 で contracts/ に書く。
- 確かめ方の「G3」は、verifier がシミュレーターとつなぎ口で決めること。Then の値はすべて G3 で決まる。「G4」は実機でしか決まらないことで、Then に入れず、この節の末尾の「G4 で Takuma が実機で確かめること」に置いた（18 の V1 の推奨 (b) の形。Takuma が (a) か (c) を選んだら、その行を G3 の前に行う）。
- 効く機会の「当たり前」は、空、エラー、オフライン、権限（審査ガイドライン 5.1.1 の、許可とデータの扱い）の AC だけに使う。
- 画面の流れ：終わりの画面と `session.tooShort` の知らせからは、1回の操作で本の一覧に戻る（形と文言は designer が G1 で決め、G3 で design-reviewer が見る）。

- AC-1：本がないときの一覧
  - Given：本0冊、記録0件、`idle`（H1）
  - When：アプリを開く
  - Then：文言キー `books.empty.message` が1つと、識別子 `books.add` の要素がちょうど1つ出る。「読む」は0個、識別子 `books.flipHint` の要素は0個。
  - 確かめ方：G3：画面のテスト（H1、H12）。G4：なし
  - 効く機会：当たり前（空）
- AC-2：本を加える
  - Given：本0冊（H1）で、本の追加の画面が開いている
  - When：次の4通りで加える。(1) タイトル「a」、著者なし (2) タイトル100字（結合した絵文字 U+1F468 U+200D U+1F469 U+200D U+1F467 を1字として含む）、著者100字 (3) タイトル「　こころ　」（前後に全角スペース）、著者「 夏目漱石 」（前後に半角スペース） (4) タイトル「こころ」、著者は全角スペース2つだけ
  - Then：どの通りでも本が1冊になり、一覧の先頭の行のタイトルは、入れた文字から前後の空白を除いたもの（(3) は「こころ」）。著者は (2) で入れた100字、(3) で「夏目漱石」が出て、(1) と (4) では著者の表示が0個。
  - 確かめ方：G3：画面のテスト（H1、H13。文字の入れ方は verifier が決める）。G4：なし

  - Given：本 A があり、`idle`、本の一覧が前面で、読み始めの保存が次の1回失敗する（H2、H7 の `session.start:1`）

  - 効く機会：当たり前（エラー）

  - Given：本 A（記録2件：20分、30分）があり、次の保存の1回が失敗する（H2、H7 の `book.add`、`book.update`、`book.delete`、`record.update`、`record.delete` のどれか1つ）

- 伏せた向きの扱い：
  - 取り方は UIDevice の向き（faceDown）にする（tech-lead の推奨。docs/reviews/001-reading-session-G0-tech-lead-flip-research.md の 1）。Apple の文書には、許可も Info.plist の説明文も出てこない［公開情報 https://developer.apple.com/documentation/uikit/uidevice/orientation ］。実機で許可のダイアログが出ないか、縦の固定がオンでも届くかは、実機の確かめ①〜③（18）で見る。結果で変わることは 10 に書いた。
  - 向きを読むのは、本の一覧が前面にあり、`idle` で、本が1冊以上、伏せる道がオン、シートと確認の画面が出ていない間だけ。ほかの画面、読書中、アプリが後ろにいる間は読まない（H17 の `flipMonitoring` で確かめる。AC-28、AC-29、AC-33）。
  - 一覧が前面になってから伏せた向きに変わり、それが1.0秒続いたら始める（AC-26、AC-27、AC-29）。始まったら向きを読むのをやめる。
  - 向きの値は端末の中だけで使い、保存も送信もしない。イベントに入れるのは始まり方（`start_method`）だけ（15）。
  - 近接センサーと、画面を点けたままにする設定は使わない（AC-12）。
  - 伏せの待ちの1.0秒を、G4-7 と G4-9 の結果で 0.5〜2.0秒の間に変える必要が出たら、Takuma の承認を取って 12 と、AC-26、AC-27、AC-31、AC-36 の値を直す。
- オフラインや通信エラーのとき：すべての機能が通信なしで動く（AC-23）。イベントの送信（Q4）が失敗しても、画面の動きと保存に影響しない。
- セキュリティとプライバシー：
  - 扱う個人データは、本のタイトル、著者、読書の日時と分数、伏せる道の設定。すべて端末の中に置く。
  - 本のタイトル、著者、伏せた向きは、イベントにも外部にも送らない（G4 で reviewer がデータの流れの表で確かめる）。
  - アカウントなし。トラッキングなし。続けて使う ID（端末の ID、ランダムな ID）を送らない（15）。ATT は、ほかの会社と共有して人を追跡するアプリに求められるもので、このアプリには要らない［公開情報 https://developer.apple.com/documentation/apptrackingtransparency ］。
  - 外部への送信先は、Q4 で (b) を選んだときの計測のサービスだけ。個人データと続けて使う ID を送らないので、5.1.2(i) の許可の確認は要らない見込み（docs/reviews/001-reading-session-G0-tech-lead-r1.md その1 の 4）。送り先は、IP アドレスを残すかと、ほかのアプリのデータと合わせて広告に使うかを、tech-lead が G1 で相手の文書で確かめてから決める。
  - プライバシーポリシーは Q4 によらず要り、アプリの中のリンクを設定の画面に置く（AC-40、17）。
  - バックアップ：記録は iCloud かパソコンのバックアップに入り、新しい機種へ戻せる［公開情報 https://support.apple.com/en-us/108770 、https://support.apple.com/en-us/108771 （tech-lead の r1 その1 の 5）］。アプリを消すと記録は消える。この2つを G5 の前に docs/support/ の FAQ に書く（pdm）。
  - PrivacyInfo.xcprivacy：伏せの待ちと経過を測る時計で申告が要るかは、tech-lead が G1 の ADR で決める。UIDevice の向き、触覚、読み上げは、申告が要る API の区分にない［公開情報 https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype （tech-lead の調べもの 7）］。
- アクセシビリティ：
  - 文字の大きさ AX5 まで、全画面で文字が切れず、全部の操作ができる（G3 の performAccessibilityAudit）。VoiceOver で全部の操作ができ、読書中の画面の要素がすべて読み上げられる（G4 で Takuma）。視差効果を減らす設定のときは動きを止める。色だけで状態を伝えない。コントラストと押せる範囲は G1 の基準（44x44pt 以上）。
  - 伏せる道は近道で、主の道は「読む」。同じことが「読む」でできて（AC-5、AC-9）、伏せる道は設定で切れる（AC-33）。WCAG 2.5.4（Level A）はこの2つを求める［公開情報 https://www.w3.org/WAI/WCAG22/Understanding/motion-actuation.html ］。HIG も "offer onscreen ways to achieve the same outcome" と書く［公開情報 https://developer.apple.com/design/human-interface-guidelines/accessibility ］。
  - 伏せて始まったことは、触覚（補助）、VoiceOver の読み上げ（AC-31）、起こしたときの読書中の画面の3つで伝え、触覚だけに頼らない（HIG の "Prefer using haptics to complement other feedback"［公開情報 https://developer.apple.com/design/human-interface-guidelines/playing-haptics ］）。
  - 触覚は iOS で鳴る種類を1回（10）。種類は designer が G1 で決める。
- 言語：日本語と英語。文言は designer が書く。

Q4 で (b) を選んだときに送る。(a) なら何も送らない。どのイベントにも、本のタイトル、著者、伏せた向きの値、続けて使う ID（端末の ID、ランダムな ID）を入れない。I-1 と I-3 を出すための値は、端末の中で求めた真偽だけを送る（docs/reviews/001-reading-session-G0-tech-lead-r1.md その1 の 4）。

- 結び付かない理由：続けて使う ID を送らず、端末で求めた値だけを送る。Apple は、集める前に直接の識別子を取り除いたデータを結び付かないものとして扱い（"Stripping data of any direct identifiers... before collection"）、続けて使う端末の ID は Device ID として結び付くものに数える［公開情報 https://developer.apple.com/app-store/app-privacy-details/ ］。
- トラッキングでない理由：集めたデータをほかの会社のデータと結び付けて広告に使わず、データブローカーとも共有しない。送り先の SDK がそう使わないことを、tech-lead が G1 で相手の文書で確かめる［公開情報 https://developer.apple.com/documentation/apptrackingtransparency ］。
- 端末の中だけに置くデータ（タイトル、著者、記録、伏せる道の設定）は「収集」に当たらない（"Data that is processed only on device is not 'collected'"［公開情報 https://developer.apple.com/app-store/app-privacy-details/ ］）。
- error_kind は空き容量の API で求めない。申告の理由 E174.1 が、その値を端末の外に送ることを認めていない（docs/reviews/001-reading-session-G0-tech-lead-r1.md その1 の 11）。
- I-1 と I-3 の出し方（ID を使わない）：
  - I-1＝判定の期間に送られた Reading Ended（first_saved_within_24h=true）の数 ÷ 同じ期間の App First Opened の数。
  - I-3＝週 W+1 の Reading Ended（first_saved_this_week=true かつ saved_last_week=true）の数 ÷ 週 W の Reading Ended（first_saved_this_week=true）の数。週は月曜〜日曜、端末の時刻（product.md の 6）。
