# 第1部 発見（何を、なぜ作るか）

## 1. 紹介文
よむとき（仮）は、紙の本でも電子書籍でも、読む時間を残す iPhone アプリです。題名を1つ入れればその場で読み始められ（題名の入力のほかは操作3回以下。AC-4）、2回目からはアプリを開いて1回の操作で前の本の続きを始められます（AC-5）。読み終えたら今のページを1つ入れるだけで（飛ばしてもよい。AC-9、AC-10）、読んだ分数と進んだページが残り、今週の合計が見えます。同じことを紙の読書ノートに残すなら、毎回、日付、始めと終わりの時刻、ページの4項目を書きます［推測：同じ情報を残すのに要る欄の数］。冊数の制限、広告、権限の確認、登録はなく（AC-21、AC-22）、記録は端末の中だけに残ります。

## 2. 中心の Job

- 機能の面：時間とページを、書く手間なしに残し、次に開いたときに前回のページがわかる。
- 気持ちの面：「最近読めていない」を「今週は○分読めた」という手応えに変える。
- 人の目の面：001 では人に見せない。自分で確かめるだけ（人に見せる面は 003 で扱う）。

## 4. 4つの力
| 今の状況の押し | 新しいものの引き | 乗り換えの不安 | 今の習慣 |
|---|---|---|---|
| スマホに時間を取られて読めていない（E-2、［推測］）。紙のノートは毎回4項目を書く［推測］ | 題名1つで始められ、記録の入力は1つ。冊数の制限と広告がない（AC-22） | 記録が消える、タイマーがずれる（E-6、［推測］）。結局課金に誘われる（E-4、［推測］） | しおりを挟むだけで読む。読書メーターに読み終えた本だけ登録する［推測］ |

- 不安と習慣を下げる手当て：
  - 記録が消える不安：強制終了と再起動で読書中と記録が残る（AC-8、AC-18、AC-33、AC-34）。保存に失敗しても読書が消えない（AC-19、AC-35。読み始め、一時停止、再開は AC-56〜AC-61。「終える」、終える入力をやめる、60秒未満で終えるは AC-62〜AC-67）。
  - タイマーへの不安：開始の時刻から数え、閉じても進む（AC-7）。止め忘れは終えるときに直せる（AC-12）。時計が戻っても負にならない（AC-41）。
  - 課金に誘われる不安：001 は課金の画面と広告を置かない（AC-22）。
  - しおりの習慣：ページの入力を飛ばせ、しおりと併用できる（AC-10）。読書メーターと競わず、読み終えた本の登録を求めない（10）。

## 5. 機会と解決
- 根（成果）：I-1 初日の読書
- 機会（利用者の言葉は［推測］。E-2、E-4〜E-6 から言い換えた）：
  - O-1「読もうと思っても、始めるまでが面倒で、結局スマホを触ってしまう」
  - O-2「タイマーを止め忘れたり、途中で止まったりして、記録が信じられない」
  - O-3「どこまで読んだか、どれだけ読めているかがわからない」
  - O-4「無料だと冊数の制限や広告があって、記録をやめてしまう」
- 選んだ機会と理由：O-1。根の I-1 は「初めて開いてから24時間以内に5分以上の読書を1回終えた割合」（product.md の 7）なので、読み始める前に離れた人は数に入らない。O-2 と O-3 は1回目を始めた後にしか効かない。O-1 の「結局スマホを触ってしまう」は E-2（スマホに時間を取られる）と同じ向きだが、E-2 は抜粋だけ［推測］なので、選ぶ理由は I-1 の定義の側に置く。O-2 と O-3 は最初から最後まで使うための最低限だけ入れる。O-4 は 001 では「置かない」ことで応える（AC-22）。

- 作る / 作らない / 形を変える：作る。ただし 001 だけでは公開せず、v1.0（001〜003）の土台として作る。
- いちばん強い反論：読む時間を残すだけなら Bookly や Bookmory がすでに強く（E-3、抜粋）、無料の記録だけでは乗り換える理由が弱い。しかもスマホを読書の場に持ち込むこと自体が「スマホに時間を取られる」問題を強めうる。
- 作らない場合に起きること：002〜004（スマホを置いて読む、読んだ時間を形に残す、一文を残す）が載る本と読書の記録がなく、どれも作れない（product.md の 10）。Takuma の2つの指標（売上と Red Dot）はゼロのまま進まない。

# 第2部 定義（どう作り、どう測るか）

## 9. やること
読書の状態の名前：`idle`（読んでいない）、`reading`（読んでいる）、`paused`（一時停止中）、`finishing`（終える入力の途中）。同時に `reading`、`paused`、`finishing` にある読書は1件だけ。この PRD で「読書中」と書くときは、`reading`、`paused`、`finishing` のどれかにあることを指す。
文言キーと識別子は仮の名前。designer が G1 で文言を決め、名前や入力の部品を変えたら指揮役に知らせる（AC の Then も合わせて直す）。
計測は常に有効（止める設定は設定画面を持つ機能で検討する。10）。

## 10. やらないこと（非目標）と、はまりやすい所
- やらないこと（理由を1行ずつ）：

  - バーコードと書誌 API：外部への依存とカメラの権限が増え、速くなる証拠がない（5 の S-3）。
  - ロック画面、Live Activity、ウィジェット、通知：002 の Job で扱う。001 は権限を1つも求めない。
  - 連続日数、目標、「今週は読めていません」のような表示：罪悪感でやめる失敗を避ける（7 の5）。
  - 読み終えた印、感想、評価、タグ、本棚の並べ替え：読書メーターと競わない。読み終えた本は 003 で扱う。
  - 表紙の写真：003 で扱う。
  - iCloud の同期と書き出し：001 は端末の中だけ。端末のバックアップには入る（iCloud のバックアップが除くのは tmp と Caches だけ［公開情報 https://developer.apple.com/documentation/foundation/optimizing-your-app-s-data-for-icloud-backup （tech-lead r1 が開いて確認）］）。
  - 課金、Pro、広告：Pro は 003 で入れる。001 の機能は永久に無料。
  - 計測を止める設定：001 は設定画面を持たない。計測は常に有効で、止める設定は設定画面を持つ機能（003 の見込み）で検討する。送るのは 15 の匿名のイベントだけ。
  - iPad と Apple Watch：iPhone だけに絞る。
  - 本の検索（G1 で足した）：本が20冊程度までは一覧で足りる［推測］。一覧は最後に記録を保存した時刻の新しい順で、読んでいる本が先頭に来る（design/001-reading-session.md の D-31）。500冊のときの一覧の性能は 12 で扱う。要るとわかったら次の機能の PRD で扱う。
- はまりやすい所と避け方：
  - 1秒ごとに足して数えると、裏に回ったときに止まる。開始と一時停止の時刻から計算する（AC-7）。
  - 日をまたぐ読書の週の集計：読書を始めた時刻の週に数える。週の始めは端末の暦の設定に従う（AC-15、AC-44）。
  - 記録を消したときの最後のページ：最後のページは本の値として持ち、記録を消しても変えない。合計時間だけ減らす（AC-16）。
  - 総ページ数が未設定の本：進み具合（%）は出さず、最後のページだけ出す（AC-28）。
  - 前より小さいページを入れたとき（読み返し）：最後のページはその値にし、その記録の読んだページは0にする（AC-29）。
  - 止め忘れで何時間も経った読書：終えるときに分を直せる（AC-12）。直せる値は1分以上、経過の分数以下（一時停止を除く。AC-30）。
  - 利用者が端末の時刻を戻したとき：経過は0で止め、負にしない（AC-41）。
  - 終える入力をやめたいとき：終える入力の画面に「やめる」の出口を置く（形は designer が G1 で決める）。やめると状態は `reading` に戻り、`finishing` にいた時間は読書時間に数えない（一時停止と同じ扱い）。入れかけのページは残さない（AC-46）。
  - 題名の上限（下の「題名の長さと改行」）を、日本語の変換中で確定していない文字にも当てて切ると、変換が壊れるおそれ［推測］。上限は確定した文字に当て、変換中の文字には当てない。この作りが標準の部品でできないと tech-lead が G1 の設計メモで判断したときは、保存のときに先頭の100字に切る形にしてよい（どちらでも、保存される題名は100字以内）。どちらの形にしたかは tech-lead が設計メモに書き、上限に届いたときの見せ方は designer がその形に合わせる（G1 の判定で直した。tech-lead r1 の要修正1、裁定1）。
- 数と境界の決まり（AC の期待する値の元）：
  - 前の本：最後に記録を保存した本。記録が0件なら最後に追加した本（AC-5、AC-25、AC-26）。読書中（`reading`、`paused`、`finishing` のどれか。9）は、ホームに前の本で読み始める操作（`home.startReading`）を出さず、読書中の本に戻る操作（`home.resumeReading`）だけを出す（AC-27）。
  - 記録を消したときの前の本（G1 の契約の後に足した。AC はない）：前の本は、いま残っている記録から出す（残っている記録のうち、保存した時刻がいちばん新しい記録の本）。消した記録は数えない。いちばん新しい記録を消すと、その次に新しい記録の本が前の本になる（例：「坊っちゃん」の記録を2日前、「こころ」の記録を1日前に保存し、「こころ」の記録がその1件だけのとき、その記録を消すと前の本は「坊っちゃん」になる）。記録を消して0件になったら、記録から出す前の本はなく、AC-26 の形（最後に追加した本）になる。記録を消しても本の最後のページは変えない（AC-16）が、前の本は変わりうる
  - 読書の終わりの時刻：「終える」操作の時刻。`finishing` の間（ページと分の入力、保存の失敗と再試行）は経過を進めない（AC-19、AC-34、AC-45）。
  - 読み始め、一時停止、再開の保存に失敗したとき（G1 の判定で足した）：状態を変えず、その画面（読み始めはホームか本の詳細、一時停止と再開は読書中の画面）に `error.saveFailed` と `error.retry` を出す。再試行が通った時刻を、読み始め、一時停止、再開の時刻にする。失敗から再試行が通るまでの間は元の状態のまま数える（`reading` なら経過は進み、`idle` と `paused` なら進まない。AC-56〜AC-61）。
  - 「終える」、終える入力をやめる、60秒未満で終える、の保存に失敗したとき（G1 の契約の後に足した）：上の行（読み始め、一時停止、再開）と同じ形にする。状態を変えず、操作した画面（「終える」と60秒未満で終えるは読書中の画面、やめるは終える入力の画面）に `error.saveFailed` と `error.retry` を出し、再試行が通れば本来の状態になる（「終える」は `finishing` になって終える入力を開き、やめるは `reading` に戻って終える入力を閉じ、60秒未満は `idle` になって本の詳細に出る）。失敗の間は、「終える」なら終える入力を開かず、やめるなら終える入力を閉じずに入れかけのページと分を残し、60秒未満なら読書を消さず記録も増やさない。再試行が通った時刻を「終える」とやめるの時刻にする（「終える」はその時刻を読書の終わりの時刻にし、やめるはその時刻までの `finishing` の時間を読書時間に数えない）。失敗から再試行が通るまでの間は元の状態のまま数える（`reading` なら経過は進み、`paused` と `finishing` なら進まない）。終える入力を下へスワイプして閉じたとき（AC-48）の保存の失敗も、やめるの失敗と同じ結果にする（閉じかけたシートを保つか開き直すかは tech-lead と designer が決める。要確認）。60秒未満で終える保存に失敗した後、再試行の時点で経過が60秒以上になっていたときの扱いは未定（18 の 6）。AC-62〜AC-67
  - 丸め：進み具合の % は切り捨て（最後のページ ÷ 総ページ数 × 100。299/300 は99%）。秒から分は切り捨て（90秒は1分）。合計（本ごと、今週）は秒で足してから分にする（90秒の記録3件は270秒で4分）。
  - 入力の範囲：題名は前後の空白（半角の空白、全角の空白 U+3000、改行、タブ）を除いて1文字以上（AC-3）。総ページ数は1〜9,999の整数か未設定（AC-31）。今のページは0〜9,999の整数で、総ページ数があればそれ以下（AC-11、AC-32）。読んだ時間は1分〜経過の分数（AC-12、AC-30）。
  - 題名の長さと改行（G1 で足した。AC はない）：題名は100字まで。1字は見た目の1文字（書記素クラスタ。結合した絵文字も1字）で数える。100字を超える分は入力できない（101字目を打っても入らず、貼り付けたときは先頭の100字だけが入る。保存のときに切る形（上の「はまりやすい所」）にしたときは、欄には100字を超えて入り、保存する値を、この行の空白と改行の決まりで整えたあとの先頭の100字にする）。保存する値は、前後の空白（AC-3 の4種）を除いたあと、中の改行（LF、CR、CRLF、U+2028、U+2029。CRLF は1つの改行）を1つずつ半角の空白1つに置き換える（並んだ改行はまとめない。タブは置き換えない）。表示では、残ったタブも空白として1行に流す（design/001-reading-session.md の 5「長い文字」と同じ）。100字の根拠は［推測：日本の本の題名は副題を含めても多くが100字に収まる］。上限を上げる変更は保存済みの題名を壊さない（18 の 5）。

## 11. 受け入れ条件

## 12. 非機能要件
- 速さ：
  - 起動から最初の画面で操作できるまで2.0秒以内。基準の機種は、最低対応 OS が動くいちばん遅い機種（tech-lead が G1 の ADR で決める）。Release ビルドを実機で XCTApplicationLaunchMetric(waitUntilResponsive: true) で5回測った中央値で見る［公開情報 https://developer.apple.com/documentation/xctest/xctapplicationlaunchmetric/init(waituntilresponsive:) （開いて確認）］。実機の測定は G4。公開後は MetricKit の起動時間の p90 で見る（MXAppLaunchMetric は iOS 27.2 で終わりの版が付いているので、後継は tech-lead が G1 で選ぶ）。
  - 読み始める操作から経過の表示まで0.5秒以内（XCTOSSignpostMetric で操作から最初の表示までを測る）。
  - 本500冊、記録10,000件で、ホームと本の詳細が1.0秒以内に出る（起動の設定で大きなデータを入れ、XCTClockMetric で測る）。
- オフラインや通信エラーのとき：通信は計測の送信だけ。送れなかったイベントを端末に貯めて後で送るか捨てるかは、未定（SDK の動きを G1 で tech-lead が確かめる）。どちらでも画面には何も出さない（AC-20）。
- セキュリティとプライバシー：扱うのは題名、総ページ数、ページ、読書の時刻と長さ。すべて端末の中に置く。外に出すのは 15 の匿名のイベントと、SDK が自動で送るものだけで、題名とページの生の値は出さない（AC-23）。アカウントなし、トラッキングなし、ATT のダイアログなし。計測の送り先は product.md の 11（TelemetryDeck の案。G1 までに無料枠と端末 ID の扱いを確かめられなければ、001 は送り先の差し替え口だけを持ち、第三者の SDK は入れない）。
- テストのつなぎ口：時計の差し替え、保存の失敗、計測の送り先の差し替え（T1〜T7）は Release ビルドで働かない。作り方は tech-lead が G1 で決め、reviewer が G2 で確かめる。
- アクセシビリティ：
  - 文字の大きさ AX5 で、経過時間とすべての操作が切れずに出る。G3 の AX5 のスクリーンショットで design-reviewer が確かめる。
  - VoiceOver ですべての操作ができ、経過時間を分と秒で読み上げる（AC-40）。経過時間を毎秒読み上げさせない。
  - 文字と背景のコントラストは4.5:1以上（大きい文字は3:1以上）。押せる範囲は44×44pt以上。
  - ダークモードに対応する。コントラストの基準はライトと同じ。
- 言語：日本語と英語。ja と en でそろっていない文言キーは0件（AC-39）。
- 電池：001 は読書中も画面の自動ロックを止めない。経過は時刻から計算するので、画面が消えても数え続ける。
- 前の版からの更新：なし（001 が最初の版）。001 の内部 TestFlight の版から次の版へ上げても記録が残ることは、002 の AC にする。

## 13. 仮説と KPI
- 仮説：初めて使う人が、初日に本を1冊入れて1回目の読書を終えるようになる。2027-02-28 までに、初日の読書が未計測から35%以上になれば正しい。

## 15. イベントとプライバシー

Save Failed の3つの操作（G1 の契約の後に足した）：session_begin_finish は「終える」（経過60秒以上）で `reading` か `paused` から `finishing` へ移る保存、session_cancel_finish は終える入力をやめる保存（下へのスワイプを含む）、session_discard は60秒未満で終えて進行中の読書を消す保存（AC-62〜AC-67）。名前は指揮役の指示書の案による。contracts/data-model.md の T5 の名前の列はこの3つでまだ「なし（未解決）」なので、tech-lead が同じ名前で T5（contracts/test-hooks.md）と contracts/telemetry.md に足す。Reading Session Discarded は消す保存が通ったときだけ送り、失敗した回は Save Failed（operation = session_discard）だけを送る。13 の「保存の失敗」の定義は変えていない。操作を分けていないので、この3つの失敗も数に入る。区分は今の Save Failed と同じ「診断：その他の診断データ」なので、プライバシー表示の区分は増えない。
