# 第1部 発見（何を、なぜ作るか）

## 1. 紹介文
「よむま」（サブタイトル「今夜も、本の続きの一行から」。product.md の 7）は、夜にスマホへ手が伸びて、紙の本を開けないまま終わる人のための読書アプリです。iPhone を手に取るとロック画面に自分の本の昨夜止めた一行が縦書きで出るので、どの本のどこから読むかを知るための操作は0回です（紙のしおりは本を探して開くまで見えず、ToRead のロック画面は読書時間と週の数字だけ）。押して iPhone を伏せればその本の読書が始まり（約4秒）、起こして終えると「p.43 → p.61　18分」と残ります。1冊を読み終えた夜にだけ、奥付（出版社、受賞）と、自分の積読から選んだ次の1冊が3冊まで出ます。毎晩の道と本の出口は無料でアカウントも要らず、本の情報を引くときに ISBN か書名を書誌のサービスに送ることと、自分で送る読み終えのカードのほかは、読んだ本の名前と一行は端末の外に出ません。
- 数字の根拠：操作0回は、利用者がロック画面にウィジェットを置いたとき（置くのは利用者。6 の 3d）。紙のしおりとの比べは［推測］。約4秒は designer の見積もり（docs/reviews/001-reading-session-integrate-designer.md の 1-1。3.5〜4.5秒）［推測］。ToRead のロック画面は「ロック画面とDynamic Islandでの読書時間の表示（ToRead Plus）」で、読み始めは「ワンタップ」なので速さでは勝てない［公開情報 E-12］。違いは、手に取った瞬間に自分の本のどこまで読んだかが見えることと、伏せる動作［推測］。本はバーコードを続けて読み、1冊ごとに登録ボタンを押さない（E-4 の不満への答え。1冊4〜6秒の見込み［推測。designer の 4-1。G4-10 で測る］）。v1.0 は利用状況を外に送らない（裁定 10、15、AC-103）。

## 2. 中心の Job
- Job ストーリー（1つだけ）：仕事のあとの夜、手がスマホに伸びかけたとき、考えずに本の続きに戻りたい。そうすれば、読みたいのに読めずに終わる夜が減る。（「続き」には、1冊を読み終えた次の夜の「次の本のはじめ」も入る）
- 機能の面：今夜どの本のどこから読むかが探さずにわかり、読んだ時間とページが残る。　気持ちの面：スマホに流された後ろめたさから離れ、少しでも本に戻れたと思える［推測］。　人の目の面：「本を読む人」でいる自分を確かめ、読み終えたことを送りたい相手にだけ伝えられる［推測］。

## 8. 推奨
- 作る。「夜の入口、本の出口」を、3週を目安の枠で（速さを測って回す所を決める。冒頭）、サーバーなしの v1 として作る。芯（毎晩の入口と本の出口）は無料にし、見た目の買い切りは、G1 で国立国会図書館の CC BY の書誌で足りると確かめられ（申請は要らない。裁定 14）、冒頭の (iii) で回さなければ v1.0 で、回せば v1.1 で足す。理由：手に取った瞬間のロック画面に本の続きを出すアプリは見た範囲（上位だけ）になく（E-12、product.md の 4）、いちばん大きいつまずき（43.6%）に当たる（E-1）。Takuma の4つは読み終えた夜だけに集めれば毎晩の道を重くせず（5、AC-86）、0人の日も動く形（積読、著者、受賞、レーベル）だけを入れる。自前のサーバーも外部の計測もないので、利用者1,000人あたりの月の費用は0ドルで、固定費は年会費だけ（16）。App Intents（アプリの外から「読み始める」、ショートカットの「どこまで読んだ？」「続きを読む」）は v1.0 の候補として回す順に入れ、Visual Intelligence は v1.1 の候補にする（Takuma の決定、2026-10-18。冒頭、9）。読み終えのふりかえりは AI を使わず、文の型で書く（E-18）。
- 条件：Q-A（伏せた向きの実機の確かめ）は G0 の承認の前に行う（Takuma の決定）。1b、2b、1c、1d、3b、3c、3d の結果は承認を待たせず、6 の分かれ道で受ける。「書誌」は G1 で tech-lead が確かめる。
- いちばん強い反論：芯の続きの一行は、毎晩止めたページを撮る手間（約5〜8秒）と、本物の紙と iPhone でまだ確かめていない読み取り（崩れと最初の待ち）に頼る（E-10）。撮らない晩が続けば、ロック画面は書名とページだけになり、ToRead や Bookmory のロック画面と変わらない（designer の 7-3）。一行が出るのも、試作と違って時計の下の小さな枠（E-9）。v1.0 は App Store Connect の数字だけなので、入口の効き目（I-2）を数で判定できない（裁定 10）。お金の面では、日本の読書の道具は稼げる型ではなく（E-16）、中くらいの場合で年約34万円［推測］。Takuma の4つは大手がすでに持ち（E-8）、当たるのは小さいつまずき（選び方 3.6%。平成25年度、E-2）の側。App Intents は Apple Intelligence そのものではなく土台で、ToRead にもショートカットがあり（E-12）、AC が増えて要る速さが上がる（冒頭）。
- 作らない場合に起きること：利用者は今のまま、紙のしおりと SNS のあいだで夜を過ごし、ブクログや読書メーターで管理し、帯や書店や人のすすめで次の本を知る［推測。E-5］。Takuma のポートフォリオの1本はできず、固定費も持ち出しのまま。伏せて読むタイマーだけの前の版に戻れば、ToRead と伏せるタイマーにはさまれる（E-12、E-13）。
- 考えを変える条件：Q-A ①が届かず、代わりの取り方に許可が要るなら、伏せる道を v1 から外す案を出す。1b と 2b がどちらも届かなければ、分かれ道どおりページ数だけを主にして進め、外部の計測を入れた版で I-4 を必ず見る。G1 で CC BY の書誌だけでは足りないと分かったら、利用申請を出すかを Takuma に聞く。出さないなら、課金を v1.1 に回す案か、書誌の出どころを見直す案を tech-lead と出す。

## 10. やらないこと（非目標）と、はまりやすい所
- やらないこと（理由を1行ずつ）：
  - 友人、フォロー、フィード、いいね、コメント、DM、順位：v1 はサーバーなし（Takuma の決定）。審査 1.2 の負担と、日本での反応の分かれ（E-15）。友人を読む前に見せるかは v1.x で決める（指揮役の裁定）。
  - 「これを読んだ人は」という名前と、集計のおすすめ：読んだ人の人数がそろうまで、他人のデータに見せない（Takuma の決定、tech-lead の 4）。
  - 新しい本を何冊も勧めること、書店へのリンク、アフィリエイト：積読が増え（E-7）、販促への不満がある（product.md の 4 の読書メーター）。新しい本は最大1冊で「積読に加える」まで。
  - 表紙の画像：openBD の書影は大きく減り（E-11）、国立国会図書館サーチの書影は国立国会図書館以外の者（出版情報登録センター（JPRO））が作ったもので、利用の条件が別［公開情報 https://www.ndl.go.jp/sitepolicy/terms 。tech-lead その2 r2 の指摘6］。文字の奥付で見せる。
  - あらすじ、レビュー、生成 AI の紹介文：確かめられない中身を出さない（5 の S-10）。
  - 統計の画面、グラフ、目標、連続日数、バッジ：連続日数は消える、お金で買えるという不満の種（integrate-pdm の 1-2 (e)）。急かさない。読み終えた夜のふりかえりの1行（この本の事実だけで、目標やほかとの比べはない）は除く。
  - 決めた時刻の通知、今夜の量、背表紙の写真、取り込み、ほかの賞、iCloud の同期、前回の最後の数行、抜き出し、一冊のしおり帳、読む手すり、Spotlight、Visual Intelligence、AI のふりかえり、Image Playground、PCC：9 の削った候補の表（Controls と Action ボタンは、Takuma の決定で v1.0 の候補に戻した。冒頭）。
  - Siri AI の自由な言い方（アプリの名前なしで「いまの本、どこまで読んだ？」と聞く形）：2026-10-18 は英語だけ（E-18）。ショートカットと BookEntity を先に作っておき、日本語が来てから後の版で足す。
  - 晩ごとのしおり（読んだ晩ごとの一行とページ）を端末に残すこと（pdm が決めた。tech-lead その1 r2 の指摘10）：v1.0 は本ごとに今のしおり1つだけを持つ。理由は、しおり帳の需要がまだ確かめられていないこと［推測］、画面に出さない本の文を利用者の知らないところにためないこと、枠が芯だけでも足りないこと（冒頭）。いちばん強い反論：v1.0 の間の晩の一行は、v1.1 でしおり帳を足しても戻せない。変えるなら、G1 で最初のデータの形を決める前に（手間は0.1〜0.25日［推測。tech-lead］）。

  - ロック画面の大きさを試作と同じに見せる：ストアの文とスクリーンショットは実際の 172×76 pt の大きさで見せ、大きく見せるのは StandBy だけ（17、審査ガイドライン 2.3）。

  - ウィジェットは利用者が置く：アプリから自動で加えられない見込み（designer の 4-2、tech-lead その1 の答え）。置き方の案内は、最初に一行を保存したあとに1回だけ出す（AC-96。形は designer が G1 で決める）。

  - ルビの崩れ：保存の前に必ず欄で直せる（AC-67）。
  - 縦書きの読み上げと大きい文字：一行全体を1つのラベルで読み上げる（12）。ウィジェットに入らないときは AC-29 の縮め方。アプリの中の大きい文字は designer が決める。

## 11. 受け入れ条件
読み方の決まり（すべての AC に効く）：
- 状態は `idle`（読んでいない）と `reading`（読書中）の2つ。`reading` のときは、アプリを前面にすると読書中の画面が出て、強制終了して開き直しても同じ本の読書中の画面に戻る。`idle` のときは読書中の画面が出ない。G3 では状態の名前を H9 で読む。
- 本の置き場所は `current`（今の本。0冊か1冊）、`tsundoku`（積読）、`finished`（読み終えた）。登録（バーコード、書名で探す、手で入れる）で本を加えたとき、今の本がなければ最初の1冊が `current` に、ほかは `tsundoku` になる。読み終えた画面の「積読に加える」（`next.addToShelf`）で加えた本は、今の本がなくても `tsundoku`（AC-83）。G3 では H13 で読む。
- 晩は、読み始めの時刻を読み始めたときのタイムゾーンで表し、4:00 より前なら前の日とした日付。記録の日付は晩の日付で出し、あとで端末のタイムゾーンが変わっても変えない。何晩は、その本の記録の晩の種類の数。
- 分数は、経過の秒を60で割って切り捨てた整数。記録が残るのは60秒以上（60秒ちょうどは1分）で、上限は1440分。本の合計は記録の分数の和。
- 字の数は、前後の空白を除いたあとの書記素（Swift の Character）の数。空白は、半角スペース、全角スペース（U+3000）、タブ、改行。保存するときは前後の空白を除き、除いた形で出す。数字の欄は全角の数字を半角に直して受け付け、数字のほかの字（小数点を含む）があれば受け付けない。
- 長さの範囲：一行は1〜60字、ページは1〜9999の整数、書名は1〜100字、著者は0〜100字。
- ウィジェットの縮め方：一行が26字以上のとき、先頭25字の中で最後の「、」か「。」が13字目以降にあればその字までを出し、なければ先頭24字と「…」を出す（AC-29）。
- 書誌から著者を取り出す決まり（登録のときと、問い合わせ直して書誌が埋まったときに1回。保存と奥付に使う。AC-92）：(1) 使う要素は、国立国会図書館サーチの dc:creator の1つ目。dc:creator がなければ、RSS の author 要素の、最後の「,」の後ろ（「,」がなければ全体。例「中林くみこ 監修」） (2) 要素を「,」と「，」で区切り、各部分の前後の空白（半角スペース、全角スペース、タブ、改行）を先に除く (3) 3つ目から後ろの部分は捨てる（生没年でも、「ピアニスト」のような限定語でも）。残った2つまでの部分のうち、数字、ハイフン、「?」だけからなる部分（生没年）も捨てる (4) 各部分の末尾にある役割の語（著、作、訳、編、文、絵、画、監修、編著、原作の10個だけ。長い語から当てる）は、その前に空白（半角か全角）か「／」があるときだけ、その空白か「／」ごと除く。部分そのものが役割の語と同じ字のとき（例「文」）と、前が名前の字のとき（例「周作」）は除かない (5) 残った部分を空白なしでつなぐ。かなか漢字を含まない著者（ラテン文字だけなど）は、半角空白を挟んでつなぐ。例：「伴名, 練, 1988-」→「伴名練」、「遠藤, 周作, 1923-1996」→「遠藤周作」、「幸田, 文, 1904-1990」→「幸田文」、「坂崎, かおる」→「坂崎かおる」、「渡邊, 朋子, ピアニスト」→「渡邊朋子」、dc:creator がなく author 要素が「中林くみこ 監修」の書誌→「中林くみこ」。H20 は国立国会図書館の要素の名前（dc:creator、author）のまま返す形にする（G1 で tech-lead が契約に書く）。openBD を使うと G1 で決めたときの取り出し方は、G1 の ADR に書き、AC を足す（付記の G1 への申し送り）。
- 見つからなかった本の問い合わせ直し（AC-10、AC-113）：書誌が0件だった本は、利用者が書名か著者を手で直していなければ、アプリが前に来たときに、前の問い合わせから24時間以上たっていれば1回問い合わせ直す。加えてから1,080時間（45日）を過ぎたら問い合わせない。見つかったら書誌を埋め、著者は上の決まりで取り出す［24時間と45日は推測。tech-lead その1 r2 の指摘4。新着書誌情報に入るのは国立国会図書館に納入されてから約4日で（tech-lead その1 r2 が読んだ附録1 の注5）、出版から納入までの日数は書かれていない］。
- 名前のそろえ方（受賞の照合と「同じ著者」に使う。表示には使わない）：(1) NFKC に直す (2) 括弧「()」「[]」「【】」「〔〕」とその中を除く（全角の（）［］は (1) で半角になる） (3) Unicode の一般カテゴリが P（句読点）か S（記号）の字と、空白（一般カテゴリ Z の字、タブ、改行）をすべて除く。「ー」と「々」（どちらも Lm）は残す。題名と著者の両方が、そろえた形で一致したときだけ「合う」とする。上下巻（「鹿の王 上」）、旧字と新字（髙と高）、副題つきの書名は合わない（受賞を出さない側に倒す）。テストの照合の行には、合ってはいけない派生の本を混ぜる（AC-20）。
- 次の1冊の決まり（3b が合格のとき）：
  - 候補は最大3冊。積読の本を、同じ著者、同じ賞、同じレーベル、どれも重ならない、の順に並べ、同じ順なら積読に加えた日が新しい順。
  - 新しい本（本棚にない本）は最大1冊で、いつも最後。出どころは受賞の一覧だけで、読み終えた本の賞（複数なら芥川龍之介賞、直木三十五賞、本屋大賞の順で最初の賞）の、すぐ後の回（本屋大賞は次の年）の本。後の回がなければすぐ前の回、同じ回に複数あれば一覧の順で最初。その本がすでに本棚にあれば、新しい本は出さない。新しい本があるときは、積読から2冊まで。
  - 理由の行は1つ。種類は「同じ著者」「同じ賞」「同じレーベル」「積読から」の4つだけ。積読の本は「積読から」に重なりを1つ添え（重ならなければ「積読から」だけ）、新しい本は「同じ賞」と回を出す。書き方は design/ に従う。
- Live Activity の予約の決まり：
  - 予約する時刻は、その晩に記録が残っていれば、晩の日付の翌日の入口の時刻。残っていなければ、まだ来ていない次の入口の時刻。
  - 予約を見直すのは、アプリが前に来たとき、記録が残ったとき、しおり（一行かページ）が変わったとき、今の本が変わったとき、入口の時刻か「一行と書名を出さない」設定を変えたとき。
  - 見直した結果の始まりの時刻と中身（書名、一行、ページ）が今の予約と同じなら、何もしない。違えば、今の予約を取り消してから新しく予約する。予約はいつも1件で、今の本がなければ取り消すだけ。
  - Live Activity が使えないとき（areActivitiesEnabled が偽）は予約しない。予約の要求が失敗したら alert を出さず、次にアプリが前に来たときに見直す（AC-97）。
  - 中身の古くなる時刻（staleDate）は、始まる晩の次の 4:00。アプリが前に来たとき、前の晩から続いている Live Activity があれば終わらせる（AC-98）。
- アプリの外からのインテント（App Intents）の決まり（AC-114〜AC-126。名前、言い方、文は仮で、G1 で designer と tech-lead が決め（付記の G1-15）、design/ の対応表を正とする。G3 は H32 でインテントを直接動かして決め、システムの入口（Control、Action ボタン、Siri の聞き取り、ロック画面での見え方）は G4 の G4-21、G4-22 で見る）：
  - 「読み始める」：今の本があり `idle` なら、アプリを前に出さずに `reading` にし、すぐ始める Live Activity を1つ出す。中身は書名（「一行と書名を出さない」がオンなら文言キー `widget.hidden` の文）と読み始めの時刻（経過時間はそこから数えて出す）で、一行とページは出さない。押せる要素は「終える」（識別子 `liveActivity.end`）の1つだけ。まだ始まっていない予約があれば取り消し、今夜の予約した Live Activity がすでに始まっていれば、新しく始めずにそれを `reading` にする（AC-41 と同じ更新）。Live Activity はいつも1つ。
  - 「読み始める」の場合分け：今の本がなければ、アプリを前に出してしおりの画面を出す（読書は始めない）。`reading` なら何もしない（読書は1つだけ。声の文言キーは `intent.start.alreadyReading`）。Live Activity が使えない（areActivitiesEnabled が偽）なら、`reading` にしてアプリを前に出し、読書中の画面を出す（外に「終える」がないため）。保存に失敗したら `idle` のままで、文言キー `session.start.error` を返す。
  - 「終える」（Live Activity のボタン）：押した時刻で読書を終えて記録を残し（1分未満、1440分、端末の時刻の決まりはアプリの中と同じ）、Live Activity を終わらせ、アプリを前に出してしおりを挟む画面を出す（1分未満なら `session.tooShort` を出してしおりの画面）。ロックを外さずに置いたときも記録は押した時刻で残り、次にアプリが前に来たときはしおりの画面を出す（しおりは AC-64 の道で挟める）。
  - 「どこまで読んだ？」：今の本のしおりのページを、文の型（文言キー `intent.whereStopped.page`。例「61ページからです。」）に入れて、声の全文として返す。一行、書名、アプリの名前は声に入れない（HIG。designer の調べもの）。ページがなければ `intent.whereStopped.noPage`、今の本がなければ `intent.whereStopped.noCurrent`。答えはアプリの記録だけから組み、AI で文を作らない。アプリを前に出さない。小窓（snippet）を出すか、出すなら何を載せるかは G1 で designer が決める（一行を載せるなら、下の認証の決まりに従う）。
  - 認証：「一行と書名を出さない」がオンでロック中なら、「どこまで読んだ？」は答える前に認証を求め、通らなければ何も返さない。オフなら、ロック中でも答える（ロック画面のウィジェットにもページが出ているため。pdm が決めた）。
  - 「続きを読む」：アプリを前に出し、しおりの画面を出す。
  - App Shortcuts の言い方には、どれもアプリの名前を入れる（HIG）。「よむまで〜」の形は使わない（「読むまで」と聞こえる。designer の調べもの）。
  - 入口の印：「読み始める」で始めた読書は `intent_start`。「続きを読む」で開いて300秒以内に、アプリが後ろに回らずに始めた読書は `intent_open`（AC-40 と同じ決まり）。v1.0 では送らない。I-2 には数えない（続きの一行を押していないため。product.md の 6）。

- 伏せた向きの扱い（前の版から変えない。「本の一覧」を「しおりの画面」に読み替える）：UIDevice の向き（faceDown）で取り、しおりの画面が前面、`idle`、今の本あり、伏せる道オン、シートと確認の画面なしの間だけ読む。向きの値は保存も送信もしない。近接センサーと、画面を点けたままにする設定は使わない（AC-54）。伏せの待ちの1.0秒を G4-7 と G4-14 の結果で 0.5〜2.0秒の間に変えるときは、Takuma の承認を取って 12 と AC-44、AC-45、AC-49、AC-59 を直す。
- オフラインや通信エラーのとき：毎晩の道（ウィジェット、Live Activity、読む、終える、しおり）は通信なしで全部動く（AC-62）。登録は ISBN を先に残して順番待ちにし（AC-9）、書名で探すときだけ通信が要る（AC-6）。受賞の一覧はアプリの中にあり、通信なしで照合できる。購入の画面は通信なしなら使えないと知らせ、ほかの機能は使える（AC-110）。v1.0 は利用状況を送らない（AC-103）。
- セキュリティとプライバシー：
  - 扱う個人データ：本の書名、著者、ISBN、出版社、置き場所、一行、ページ、読書の日時と分数と入口の印、設定、購入の状態。すべて端末の中に置く。アカウントなし。
  - 保存先：主の保存先はアプリの Application Support に置き、ウィジェットと分け合う App Group には小さな写し（今の本の書名、一行、ページ、出さない設定）だけを置く。写しはロック中にウィジェットが読むので、保護の等級は「最初のロック解除まで」より強くしない（tech-lead その1 の指摘9。G1 の ADR）。
  - 外部への送信先：書誌の問い合わせだけ（国立国会図書館サーチに書名か ISBN。openBD を使うと G1 で決めたら、openBD に ISBN。AC-103）。v1.0 は外部の計測を使わない（裁定 10）。Live Activity は push で更新しない（ActivityKit の request の pushType を nil にし、push のトークンを作らない。tech-lead その1 r2 の指摘6）。購入は Apple の StoreKit が扱い、アプリは購入の情報を外に送らない。書誌の問い合わせがプライバシー表示の「収集」に当たるかは、当たらない見込み（送り先はこちらがコードを入れた相手でなく、開発者は中を読まない［推測。tech-lead その1 の答え］）。tech-lead が G1 で、reviewer が G5 で決める。当たるなら、書名で探すのは「検索履歴」。
  - 写真と読み取った文：撮ったページは読み取りのあいだだけメモリの中で使い、保存しない。写真ライブラリに書かない。読み取った文のうち保存するのは選んだ一行だけ（AC-69）。撮り方（一時ファイルを書かない形）は tech-lead が G1 で決める。
  - ロック画面：一行と書名は周りの人にも見えるので、出さない設定を置く（AC-34）。読まなかった晩の Live Activity は翌朝に残さない（AC-98）。
  - アプリの外からのインテント：システム（Siri、ショートカット、ロック画面）に渡すのは、Live Activity の書名と読み始めの時刻、「どこまで読んだ？」の答え（ページ）と小窓の中身。開発者には何も届かない。Siri の声は周りの人にも聞こえるので、一行を声に出さず（AC-121）、出さない設定ならロック中は認証のあとでだけ答える（AC-123）。ロック中に開かずに読み始めを保存するための保護の等級は、G1 で tech-lead が ADR で決める（付記の G1-16）。
  - トラッキングなし。ATT は要らない［公開情報 https://developer.apple.com/documentation/apptrackingtransparency ］。
  - プライバシーポリシーは要り、設定の画面にリンクを置く（AC-88、17）。書誌の問い合わせの送り先、購入は Apple が扱うこと、v1.0 は利用状況を送らないことを書く。
  - バックアップ：記録は iCloud かパソコンのバックアップに入り、新しい機種へ戻せる［公開情報 https://support.apple.com/en-us/108770 、https://support.apple.com/en-us/108771 （前の版で tech-lead が引いたもの）］。App Group の入れ物が戻らない報告があるので（tech-lead その1 の指摘9）、主の保存先を App Group に置かない（G4-17 で確かめる）。アプリを消すと記録は消える。この2つを G5 の前に docs/support/ の FAQ に書く（pdm）。
  - PrivacyInfo.xcprivacy：時計の API と、App Group で分け合う保存先に申告が要るかを、tech-lead が G1 の ADR で決める。
- アクセシビリティ：
  - 文字の大きさ AX5 まで、アプリの全画面で文字が切れず、全部の操作ができる（G3 の performAccessibilityAudit）。縦書きの一行は自前の組みなので、大きい文字のときの見せ方は designer が G1 で決める。ウィジェットは枠より大きくできないので、大きい文字の人には、押して開いたしおりの画面の `bookmark.line` で全文を出す（AC-29）。
  - ウィジェットとしおりの画面の一行は、全体を1つのラベルとして読み上げ、ラベルは縦書き用の字でなく保存した一行から作る（AC-99、G4-13）。
  - 伏せる道は近道で、主の道は「読み始める」。同じことが「読み始める」でできて（AC-42、AC-43）、伏せる道は設定で切れる（AC-51）。WCAG 2.5.4（Level A）はこの2つを求める［公開情報 https://www.w3.org/WAI/WCAG22/Understanding/motion-actuation.html ］。
  - 伏せて始まったことは、触覚、読み上げ（AC-49）、起こしたときの読書中の画面の3つで伝え、触覚だけに頼らない［公開情報 https://developer.apple.com/design/human-interface-guidelines/playing-haptics ］。
  - バーコードと撮る道には、手で入れる道を必ず並べ（AC-5、AC-12、AC-63、AC-70）、カメラを使えない人も全部の機能を使える。
  - アプリの外の入口（AC-114、AC-121）は、伏せられない人と画面を見にくい人に、ボタン1回の道（Control、Action ボタン）と声の道（Siri）を足す［推測。designer の調べもの］。Control には読み上げのラベル（文言キー `control.startReading`）を付ける（AC-126）。
  - 色だけで状態を伝えない。押せる範囲は 44×44 pt 以上。動きを減らす設定のときは動きを止める。ロック画面と暗い StandBy の vibrant の描き方でも読める字の太さにする（designer）。
- 言語：日本語と英語。文言は designer が書く。縦書きは、かなか漢字を含む一行だけ（AC-30）。

## 14. 撤退基準
公開の前に決め、後から動かさない。判定は pdm 以外の役が行う。どの行も、行動を決めるのは Takuma。
- 公開日は、JP の App Store で配信が始まった日（日本時間）。実際の日付は、公開の日に指揮役が docs/approvals/ の G6 の記録に書く（docs/org/gates.md の G6）。「公開28日後」は、その日から数えて28日目の暦の日。「課金を入れた版の公開」は、課金の入った版が配信された日（v1.0 に入れば公開日と同じ）。

- プライバシー表示の見込み：「データの収集なし」。tech-lead が G1 で、reviewer が G5 で決める。

## 16. 収益化への影響

## 17. 審査と法務で気をつけること
- 4.3(b)（ありふれた分野）："simple timers" を名指しし、"meaningfully different or improved experience" がなければ新しい提出を受け付けない［公開情報 E-14］。読書の記録とタイマーは多くあり、伏せるタイマーもある（E-12、E-13）。違いは、ロック画面の縦書きの一行（自分の本の止めた行）、伏せて読む、読み終えた夜の本の出口がつながった体験として説明する。
  - 審査メモ（2.3.1(a) は具体的に書くことを求める［公開情報 https://developer.apple.com/app-store/review/guidelines/ ］）：
    - 1文（日本語）：「本を1冊加えて止めた一行を入れると、その一行がアプリのしおりの画面とロック画面のウィジェットに縦書きで出ます。しおりの画面で iPhone を伏せて置くと、ボタンを押さずにその本の読書が始まり、終えるとページと時間が残ります。本を読み終えた夜にだけ、奥付（出版社、受賞）と積読からの次の1冊が出ます。」
    - 1文（英語）："Add a book and save the line where you stopped reading: it appears in vertical Japanese type on the app's bookmark screen and on the Lock Screen widget. Place iPhone face down on the bookmark screen and a reading session for that book starts without a tap; when you end it, the page and time are saved. Only on the night you finish a book does the app show its colophon (publisher, awards) and up to three next books from your own to-read pile."
    - 確かめる手順（約60秒）：1)「本を加える」→「手で入れる」で書名を1つ入れる 2) しおりの画面の「どこまで読んだかを入れる」（AC-64）→「手で入れる」で一行とページを入れる（縦書きで出る） 3) iPhone を机に伏せて置く（触覚が1回）。起こすと、書名と「終える」だけの読書中の画面が出る。ロック画面のウィジェットの置き方を1行添える。
    - 添える1文：「1分未満の読書は記録に残りません。記録を確かめるときは、1分以上たってから『終える』を押してください。」
    - 添える1文（2.5.14 のため）：「伏せて始まったときは、触覚、読み上げ、読書中の画面の3つで知らせ、設定で切れます。」
  - 却下されたとき：審査メモと App Review への返信で違いを説明し直し、1回だけ出し直す。2回目も 4.3(b) で却下されたら出し直しをやめ、方向を見直す案を pdm が Takuma に出す（却下の理由を読むのは reviewer、決めるのは Takuma）。
- 2.3（正確さ）：掲載文、スクリーンショット、プライバシー表示を実際の体験に合わせる。
  - ロック画面の一行は、時計の下の小さな枠（172×76 pt）に出る。大きな一行の絵は、StandBy か、アプリの中のしおりの画面として見せ、10秒の試作の大きさをロック画面として見せない。
  - 「伏せるだけで始まる」と書くなら、しおりの画面が前面にあるときだけと分かるように書く。「何も外に送らない」とは書かない（書誌の問い合わせがある）。
  - 有料の見た目は、掲載文とスクリーンショットで有料と分かるようにし、何に払うかをはっきり示す（2.3、2.3.2。文言は reviewer に要確認）。ロック画面の長方形のウィジェットでは紙の色が出ないので、ロック画面の色まで変わるように見せない（16）。
- ウィジェットと Live Activity の決まり（HIG）：ロック画面のウィジェットは、それだけで役に立つ情報にする（"Provide useful information in your Lock Screen widget, and don't treat it as an additional way for people to launch into your app."［公開情報 https://developer.apple.com/design/human-interface-guidelines/widgets 。designer の 1-0 が引いたもの］）。続きの一行は情報として成り立つ。Live Activity は "work best for tracking short to medium duration activities that don't exceed eight hours"［公開情報 https://developer.apple.com/design/human-interface-guidelines/live-activities ］なので、「今夜の読書」（待つ → 読む → 結果）という始まりと終わりのある活動として作る（AC-41）。
- App Intents と Siri（HIG）：App Shortcuts の言い方にはアプリの名前を入れ、Siri の答えは短くし、アプリの名前を入れない［公開情報 https://developer.apple.com/design/human-interface-guidelines/app-shortcuts 、https://developer.apple.com/design/human-interface-guidelines/siri 。designer の調べもの（docs/reviews/001-reading-session-apple-intelligence-designer.md の 2-2）が 10-18 に読んだ］。v1.0 の App Intents は Apple Intelligence そのものではない（E-18）ので、掲載文、スクリーンショット、審査メモに「Apple Intelligence 対応」と書かない（2.3.1(a)）。Visual Intelligence を足す版で見直す。
- 3.1.1（App 内課金）：買い切りの見た目は App 内課金で売る。復元の仕組みを置く（"you should make sure you have a restore mechanism for any restorable in-app purchases"［公開情報 https://developer.apple.com/app-store/review/guidelines/ 。money-pdm の 3 が引いたもの］。AC-108）。試用は置かない（16）。購入のシートは標準の部品を使い、システムの確認のシートをまねない（designer の 3-4）。定期課金の決まり（3.1.2）は当たらない。
- 4.2（最低限の機能）：保存するデータ、登録、本棚、ウィジェット、Live Activity があり、低い（tech-lead の 6）。G5 で reviewer が確かめる。
- 1.2（他人の投稿）、5.1.1(v)（アカウントの削除）、5.1.2（連絡先）、4.8（ログイン）：v1 はどれもかからない（友人もアカウントもない。tech-lead の 6）。友人を足すときに見直す。
