# 第1部 発見（何を、なぜ作るか）

## 1. 紹介文
よむとき（仮）は、紙の本でも電子書籍でも、読む時間をそっと残す iPhone アプリです。題名を1つ入れればその場で読み始められ、2回目からはアプリを開いて1回の操作で前の本の続きを始められます。読み終えたら今のページを1つ入れるだけで、読んだ分数と進んだページが残り、今週の合計が見えます。紙の読書ノートなら毎回書く4項目（日付、始めと終わりの時刻、ページ）［推測］が入力1つになり、Bookly の無料版の10冊の上限［公開情報（抜粋） https://makeheadway.com/blog/bookly-app-review/ ］も広告もありません。登録は要らず、記録は端末の中だけに残ります。

## 2. 中心の Job
- Job ストーリー（1つだけ）：本を開いて読み始めるとき、読んだ時間と進んだページを手間なく残したい。そうすれば、次は前回のページから読み始められ、どれだけ読めているかを確かめられる。
- 機能の面：時間とページを、書く手間なしに残し、次に開いたときに前回のページがわかる。
- 気持ちの面：「最近読めていない」を「今週は○分読めた」という手応えに変える。
- 人の目の面：001 では人に見せない。自分で確かめるだけ（人に見せる面は 003 で扱う）。

## 4. 4つの力
| 今の状況の押し | 新しいものの引き | 乗り換えの不安 | 今の習慣 |
|---|---|---|---|
| スマホに時間を取られて読めていない（E-2）。紙のノートは毎回書くのが手間［推測］ | 題名1つで始められ、記録の入力は1つ。冊数の制限と広告がない | 記録が消える、タイマーがずれる（E-6）。結局課金に誘われる（E-4） | しおりを挟むだけで読む。読書メーターに読み終えた本だけ登録する［推測］ |

- 不安と習慣を下げる手当て：
  - 記録が消える不安：強制終了と再起動で読書中と記録が残る（AC-8、AC-18）。保存に失敗しても読書が消えない（AC-19）。
  - タイマーへの不安：開始の時刻から数え、閉じても進む（AC-7）。止め忘れは終えるときに直せる（AC-12）。
  - 課金に誘われる不安：001 は課金の画面と広告を0回にする（AC-22）。
  - しおりの習慣：ページの入力を飛ばせ、しおりと併用できる（AC-10）。読書メーターと競わず、読み終えた本の登録を求めない（10）。

## 5. 機会と解決
- 根（成果）：I-1 初日の読書
- 機会（利用者の言葉は［推測］。E-4〜E-6 の不満から言い換えた）：
  - O-1「読もうと思っても、始めるまでが面倒で、結局スマホを触ってしまう」
  - O-2「タイマーを止め忘れたり、途中で止まったりして、記録が信じられない」
  - O-3「どこまで読んだか、どれだけ読めているかがわからない」
  - O-4「無料だと冊数の制限や広告があって、記録をやめてしまう」
- 選んだ機会と理由：O-1。I-1 は「初日に1回目の読書を終える」ことなので、始めるまでの手間がいちばん効く［推測］。O-2 と O-3 は最初から最後まで使うための最低限だけ入れる。O-4 は 001 では「置かない」ことで応える。

|---|---|---|
| S-1 題名だけで本を登録し、その場で読み始める | 採る | 入力1つで1回目の読書に入れる（O-1） |

## 8. 推奨
- 作る / 作らない / 形を変える：作る。ただし 001 だけでは公開せず、v1.0（001〜003）の土台として作る。
- いちばん強い反論：読む時間を残すだけなら Bookly や Bookmory がすでに強く（E-3）、無料の記録だけでは乗り換える理由が弱い。しかもスマホを読書の場に持ち込むこと自体が「スマホに時間を取られる」問題を強めうる。
- 作らない場合に起きること：002〜004（スマホを置いて読む、読んだ時間を形に残す、一文を残す）が載る本と読書の記録がなく、どれも作れない。Takuma の2つの指標（売上と Red Dot）はゼロのまま進まない。

# 第2部 定義（どう作り、どう測るか）

## 9. やること
読書の状態の名前：`idle`（読んでいない）、`reading`（読書中）、`paused`（一時停止中）、`finishing`（終える入力の途中）。同時に `reading`、`paused`、`finishing` にある読書は1件だけ。
文言キーと識別子は仮の名前。designer が G1 で文言を決め、名前を変えたら指揮役に知らせる。

| やること | Kano（［推測］） | 効く機会（O-n） |
|---|---|---|
| 題名だけで本を追加する（総ページ数は任意） | 当たり前 | O-1 |
| 本を選んで読み始め、一時停止、再開、終える | 当たり前 | O-1 |
| 前の本をホームから1回の操作で読み始める | 性能 | O-1 |
| 開始の時刻から経過を数え、閉じても強制終了しても保つ | 当たり前 | O-2 |
| 終えるときに今のページを入れる（飛ばせる） | 性能 | O-3 |
| 終えるときに読んだ時間を分で直す | 当たり前 | O-2 |
| 1分未満の読書は記録しない | 当たり前 | O-2 |
| 本ごとの合計時間、記録の数、最後のページ、進み具合 | 性能 | O-3 |
| 今週の合計時間 | 性能 | O-3 |
| 記録を消す | 当たり前 | O-2 |
| 冊数の制限、広告、課金の画面を置かない | 魅力 | O-4 |
| 題名を送らない匿名の計測 | 当たり前 | 当たり前 |

削った候補（RICE。Reach は四半期の新規3,000人［推測］、時間の枠で割る）：
- ISBN のバーコードと書誌検索：3,000 × 1 × 50% ÷ 1週 = 1,500。外部 API とカメラの権限が増え、題名1つの入力より速い証拠がない。
- ロック画面の表示（Live Activity）とウィジェット：2,100 × 2 × 50% ÷ 1週 = 2,100。点は高いが別の Job（スマホに引き戻されない）なので 002 で扱う。
- 連続日数と目標：3,000 × 0.5 × 50% ÷ 1週 = 750。罪悪感を生むおそれ（7 の5）。
- 表紙の写真：1,500 × 1 × 50% ÷ 1週 = 750。003 で扱う。

## 10. やらないこと（非目標）と、はまりやすい所
- やらないこと（理由を1行ずつ）：
  - 001 だけを App Store に出すこと：単独では 4.3(b) の simple timers に当たるおそれがある（E-7）。内部の TestFlight までにする。
  - バーコードと書誌 API：外部への依存とカメラの権限が増え、速くなる証拠がない（5 の S-3）。
  - ロック画面、Live Activity、ウィジェット、通知：002 の Job で扱う。001 は権限を1つも求めない。
  - 連続日数、目標、「今週は読めていません」のような表示：罪悪感でやめる失敗を避ける（7 の5）。
  - 読み終えた印、感想、評価、タグ、本棚の並べ替え：読書メーターと競わない。読み終えた本は 003 で扱う。
  - 表紙の写真：003 で扱う。
  - iCloud の同期と書き出し：001 は端末の中だけ。端末のバックアップには入る（要確認 tech-lead）。
  - 課金、Pro、広告：Pro は 003 で入れる。001 の機能は永久に無料。
  - iPad と Apple Watch：iPhone だけに絞る。
- はまりやすい所と避け方：
  - 1秒ごとに足して数えると、裏に回ったときに止まる。開始と一時停止の時刻から計算する（AC-7）。
  - 日をまたぐ読書の週の集計：読書を始めた時刻の週に数える。週の始めは端末の暦の設定に従う（AC-15）。
  - 記録を消したときの最後のページ：最後のページは本の値として持ち、記録を消しても変えない。合計時間だけ減らす（AC-16）。
  - 総ページ数が未設定の本：進み具合（%）は出さず、最後のページだけ出す。
  - 前より小さいページを入れたとき（読み返し）：最後のページはその値にし、その記録の読んだページは0にする。
  - 止め忘れで何時間も経った読書：終えるときに分を直せる（AC-12）。直せる値は1分以上、経過の分数以下（一時停止を除く）。

## 11. 受け入れ条件
1つの AC に1つのふるまい。時刻を使う AC は、テストで時計を差し替えてよい（方法は tech-lead が G1 で決める）。

- AC-1：本が0冊のときは、空の状態と本を追加する操作だけが出る
  - Given：本が0冊、記録が0件で、初めてアプリを開いた
  - When：最初の画面が出る
  - Then：空の状態の文言（キー `library.empty.title` と `library.empty.message`）と、本を追加する操作（識別子 `library.addBook`）が1つだけ表示され、読み始める操作は0個
  - 確かめ方：画面のテストとスクリーンショット
  - 効く機会：当たり前
- AC-2：題名だけで本を追加できる
  - Given：本を追加する入力が開いている
  - When：題名に「坊っちゃん」を入れ、総ページ数を空のまま保存する
  - Then：本が1冊になり、題名「坊っちゃん」、総ページ数は未設定（nil）、最後のページは0で保存される
  - 確かめ方：画面のテスト
  - 効く機会：O-1
- AC-3：題名が空では本を追加できない
  - Given：本を追加する入力で、題名が空か空白だけ
  - When：保存しようとする
  - Then：保存の操作（識別子 `book.save`）は無効（isEnabled が false）のままで、本の数は変わらない
  - 確かめ方：画面のテスト
  - 効く機会：当たり前

## 12. 非機能要件
- 速さ：アプリを起動してから最初の画面で操作できるまで2.0秒以内（iPhone 12 相当、要確認 tech-lead）。読み始める操作から経過の表示まで0.5秒以内。本500冊、記録10,000件で、ホームと本の詳細が1.0秒以内に出る。
- オフラインや通信エラーのとき：通信は計測の送信だけ。送れないときは端末に貯めて後で送るか捨て、画面には何も出さない（SDK の動きは要確認 tech-lead）。
- セキュリティとプライバシー：扱うのは題名、総ページ数、ページ、読書の時刻と長さ。すべて端末の中に置く。外に出すのは 15 の匿名のイベントだけで、題名とページの生の値は出さない。アカウントなし、トラッキングなし、ATT のダイアログなし。計測の送り先は product.md の 11（TelemetryDeck の案、Takuma の決定待ち）。
- アクセシビリティ：文字の大きさ AX5 で、経過時間とすべての操作が切れずに出る。VoiceOver ですべての操作ができ、経過時間を「12分30秒」の形で読み上げる。文字と背景のコントラストは4.5:1以上（大きい文字は3:1以上）。押せる範囲は44×44pt以上。
- 言語：日本語と英語。ja と en でそろっていない文言キーは0件。
- 電池：001 は読書中も画面の自動ロックを止めない。経過は時刻から計算するので、画面が消えても数え続ける。

## 15. イベントとプライバシー
名前は「対象＋動作」の英語、プロパティは小文字とアンダースコア。値は区間で送り、題名とページの生の値は送らない（AC-23）。区分は App Store のプライバシー表示の分け方［公開情報 https://developer.apple.com/app-store/app-privacy-details/ （開いて確認）］。「結び付けない」は、送り先の SDK が送る匿名の ID の扱い次第で変わるので、tech-lead が G1 で確かめる。

| イベント（対象＋動作） | プロパティ | プライバシー表示の区分 | ユーザーと結び付くか | トラッキングか |
|---|---|---|---|---|
| App First Opened | なし | 使用状況データ：製品の操作 | 結び付けない（要確認） | いいえ |
| Book Added | has_total_pages（true / false）、book_count_bucket（1、2-5、6-20、21+） | 使用状況データ：製品の操作 | 結び付けない（要確認） | いいえ |
| Reading Session Started | is_first_session（true / false）、start_source（home、book_detail、after_add） | 使用状況データ：製品の操作 | 結び付けない（要確認） | いいえ |
| Reading Session Finished | duration_bucket（1-4、5-14、15-29、30-59、60-119、120+ 分）、page_entered、pages_bucket（0、1-9、10-29、30-99、100+）、minutes_edited（true / false）、was_paused（true / false）、is_first_5min（この端末で初めての5分以上の読書か、true / false）、since_first_open（0-24h、1-7d、8d+） | 使用状況データ：製品の操作 | 結び付けない（要確認） | いいえ |
| Reading Session Restored | reason（relaunch） | 使用状況データ：製品の操作 | 結び付けない（要確認） | いいえ |
| Reading Session Discarded | reason（too_short） | 使用状況データ：製品の操作 | 結び付けない（要確認） | いいえ |
| Reading Week Reached | threshold_min（60） | 使用状況データ：製品の操作 | 結び付けない（要確認） | いいえ |
| Save Failed | operation（book_add、session_finish、session_delete） | 診断：その他の診断データ | 結び付けない（要確認） | いいえ |

North Star（週の読書者数）は、その週の `Reading Week Reached` の数で数える。利用者の ID を使わずに数えられる。
