## 結論（3体がそろった所）
1. **バーコードでの一括取得は、通信なしで作れる。** 国立国会図書館が作った書誌（CC BY）をアプリの外で SQLite にまとめ、端末に置く。申請は要らない。要るのは表示の条件3つ（出典、加工したこと、NDL サーチの API で作ったこと）。
   - 見つからない本（新刊は2〜6週遅れる［推測］）は、「名前で迎える」（背か表紙を写して押す）と「あとで」に落ちる。行き止まりはない。
   - 同梱データは、名前を打つときの候補、レーベル、レコメンド（この著者のほかの本、次の巻）にも効く。
   - **バーコードは、同梱データとセットで v1.0 に戻る。** 同梱しないなら、通信なしでは番号しか出ないので使わない（前の「検討中」の答え）。
2. **デジタル書籍は、「どの本でも、写して押す」で紙と同じ道に載る。** 紙は写真、電子はスクリーンショット（許可なしで選べる）。同じ部品で、加える・続きの一行・奥付をまかなう。
   - Kindle や Apple Books に、蔵書や読書の位置を取る公開の API はない。
   - Kindle 端末や iPad で読む人は、今の「伏せて読む」がそのまま使える。同じ iPhone で読む人は、「読み始める」で計り始めて本のアプリへ移り、Live Activity の「終える」で閉じる。
   - 市場：電子の9割近くは漫画。文字ものは金額で約7%。ただし20〜40代は電子を使う人が5割を超え、多いのは「紙と電子の両方を読む人」（読む人の46%）。競合のレビューで「Kindle 本も登録したい」が繰り返し出る。
3. **レコメンドは、v1.0 で「おすすめ」と呼べる形を出せる。** 積読から（同じ著者、同じ賞、同じレーベル）に加え、同梱データで持っていない本も出す（この著者のほかの本、シリーズの次の巻、同じ賞の前後の回）。理由は事実を1行で書く。
   - 利用者の望みは3つに分かれる：積読から選ぶ、好きな作家の続き（本を選ぶ理由の1位 32%）、他人の好みで出会う。前の2つはサーバーなしで応えられる。他人の好みで出会う形（本当の「これを読んだ人は」）だけが、サーバーと人数（数千人［推測］）を要し、v2。
   - Foundation Models に選ばせる形は、spike で規則より悪かった（理由がデータと合わない 32/48、別の版を選ぶ 5/48）。使わない。
   - Apple Design Award の6部門で見ると、レコメンドは賞を取る部品ではない。「欲しいのにない」を消す部品。賞は芯（ロック画面の縦書きの一行と伏せる動作）で取りに行く。

## 3体で分かれた所と、指揮役の裁定
1. **同梱するデータの範囲**
   - tech-lead：全部（ISBN のある日本の本 約295万冊、約440〜490 MB）を Apple-Hosted Background Assets で配る。
   - pdm：アプリの大きさの増分 100 MB 以下を条件にする（大きさで入れる率が下がる相関がある）。
   - 裁定（推奨）：**v1.0 は文学（NDC 9。約40万冊、約65 MB）だけをアプリに同梱する。** 理由：asset pack を使わないので、通信は本当に0件、データの版ごとの審査もなく、pdm の線に収まる。このアプリの芯は小説と随筆の「続きの一行」。文学の外の本（新書、ビジネス書、漫画）は「一覧にない本」として写す道に落ちる。全部に広げるのは v1.1 の候補（asset pack）。Takuma に確かめる。
2. **レコメンドの置き場所**：designer の案（読み終えた夜の S-9 に3冊、今の本がない夜の S-1 に積読から3冊、読み終えた本の画面 S-7 に「この本のあとに」5冊）。S-7 の5冊は PRD 10 の「新しい本を何冊も勧めない」を緩める。裁定：S-9 と S-1 は入れる。S-7 の5冊は Takuma に確かめる（積読を増やす向きに働くため）。
3. **ショートカットのオートメーションの案内**（同じ iPhone で読む人向けの自動の始まりと終わり）：tech-lead は v1.0 で案内の文だけ、designer は v1.1。裁定：v1.1。誤作動の報告（未確認）があり、案内だけでも「自動で始まる」期待を作るため。
4. **「デジタル書籍」の範囲**：designer の推奨どおり、文字の本だけ。漫画（電子の87.8%）とオーディオブックは入れない（「続きの一行」も「伏せる」もない）。Takuma の「メイン」が漫画を含むなら対象の層が変わるので、確かめる。
5. **「必ず達成」の読み方**：A（v1.0 に、持っていない本も出る事実の理由つきの「おすすめ」）を v1.0 で出し、B（本当の「これを読んだ人は」）は条件つきで約束する（例：公開後に月の利用者が決めた数を超えたら v2 の PRD を書く。線は PRD に書いてから動かさない）。B を v1.0 で約束すると、サーバー、同意、通信0件の約束の見直し、外部送信の問いが戻る。
