## 結論
- **形は変えません**（夜の入口、本の出口）。4体とも、別の方向を芯にすることは推しませんでした。
- **ローカル AI のあらすじは、今は v1 に入れません。**
  - pdm と designer は、「前回のあらすじ」を有料の芯に推しました。
  - しかし tech-lead の spike では、端末の AI が作った2行のあらすじの36件中22件（61%）に、本文と違う事実が入りました。42回中6回は、答えが返りませんでした。
  - 語の読みも、20語中1語しか正しくありませんでした。
- **代わりに、AI なしで全機種に出せる「読む手すり」があります。**
  - 読みがな：CFStringTokenizer で、20語中20語が正解でした（語だけで試した）。
  - 端末の辞書。
  - 撮ったページの続きの読み上げ：ルビの読みがなを除く処理が要ります。
  - 前回の最後の数行：撮ったページの文を、そのまま出します。
- **収益は「芯は無料、買い切り」（money の案1）を推します。**
  - 有料にするのは、見た目、一冊のしおり帳、読む手すりです。
  - 定期課金は推しません。
- **入る額は小さい見込みです**（中くらいの場合で年約34万円［推測］）。
  - 日本のブックの売上の上位60に、読書の道具は1本もありません。
  - Takuma の「お金になる」の目安によっては、方向の見直しが要ります。

## 2. 分かれた所と、指揮役の裁定
1. **「前回のあらすじ」を有料の芯にするか**
   - ai-direction と designer は推しました。tech-lead は「難しい」と判定しました（spike で誤りが61%）。
   - **裁定：v1 には入れない。**
     - 作り話を言い切る機能は、本を読む人の信頼を失います。
     - 品質を確かめ直す条件を決めて、後の版で見直します。見直す道は、PCC、OS の更新、ページの写真を直接渡す形です。
     - v1 では、AI なしの「前回の最後の数行」を出すかを PRD で決めます。
   - 注：spike は Mac と合成のページで行いました。iPhone と本物の紙では確かめていません。tech-lead の判断への反論は reviewer に頼みました（5）。
2. **試用**
   - designer は「1冊目は全部使える」案、money は「試用なし」の案です。
   - tech-lead：買い切りの試用は、0円の非消耗型（3.1.1 の「XX-day Trial」の命名）なら作れます。
   - **裁定：PRD で決める。** 審査で通る形かは reviewer に要確認です。
3. **有料の中身に「読む手すり」を入れるか**
   - designer は「言葉の手帳」を有料に入れる案、money の案1 は見た目としおり帳です。
   - tech-lead：読みがなと辞書は全機種で動き、負担は S です。
   - **裁定：推す案に入れる。** どの機種でも動く価値に課金を付ける、という tech-lead の推しと合います。細かい中身は PRD で決めます。
4. **US 版**
   - ai-direction は、お金を主にするなら US 版の時期を決めるべきとしました。
   - **裁定：Takuma に聞く。** 今は「今のアプリを出したあとに見積もる」を推します。

## 3. 推す案（収益とローカル AI）
| 場面 | 無料 | 有料（買い切り。値段の案は ¥980［推測］） | 後の版 |
|---|---|---|---|
| 毎晩 | 続きの一行、伏せて読む、しおり、結果 | 見た目（書体、紙の色、ウィジェットと StandBy の意匠） | |
| 読む手すり | | 読みがな、辞書、続きを声で（ルビの除去つき） | |
| 本の出口 | 奥付、受賞、次の1冊、カード | 一冊のしおり帳（晩ごとの一行が並ぶ。自分だけで見る） | |
| AI | | | 前回のあらすじ（品質を確かめ直してから。対応機種だけ） |

- 課金を始める時：v1.0 からです。国立国会図書館の利用申請が間に合わなければ、v1.1 からにします。
- v1.0 の有料の中身をどこまでそろえるかは、期間の決定に合わせて PRD で決めます。いちばん安いのは見た目だけです（money の 5-4）。
- 収益の見込み［推測］：1年で 3,000〜50,000 ダウンロード、その3%が買うとして、手取りは約7万〜114万円です。中くらいの場合で約34万円（月約3万円）です。
- 撤退基準に足す収益の行の案は、money の 5-5 にあります（R-1、R-2、R-G）。

## 4. いちばん強い反論
1. **読書の道具は、日本では稼げる型ではありません。**
   - ブックの売上の上位60にある読書のアプリは、中身を売るもの（マンガ、Web 小説、Audible、要約）だけで、道具は0本です。
   - 年34万円では、事業の柱になりません。
2. **ローカル AI は、今の品質では売りにできません。**
   - 対応機種も、日本の iPhone 利用者の約4〜5割です（MMD研究所、2026年8月）。
3. **お金と映えでいちばん強いのは、別の方向の「絵本の読み聞かせに音」です。**
   - US では、この型（Novel Effect）がブックの売上29位です。
   - ただし対象が親子に変わり、Takuma が共感した課題からは外れます。

## 5. 確かめの追加（案）
- 文庫のページ5枚（予定どおり）で、tech-lead があらすじも作り、作り話の数を数える。Takuma の手間は増えない。
- 拡大鏡のアクセシビリティリーダーで、縦書きでルビのある文庫を1ページ読み上げさせる（Takuma、10分）。「続きを声で」を自前で作る意味があるかを見る。
- tech-lead の判断（AI を v1 に入れない、課金は全機種で動く価値に付ける）への反論を、reviewer に頼んだ（指揮役。報告は docs/reviews/ に保存する）。

## 追記：reviewer の判定（FAIL）を受けた訂正（2026-10-18）
- reviewer の報告：docs/reviews/001-reading-session-ai-review.md
  - 判断1（端末の AI のあらすじを v1 に入れない）は、「文を作らせる形について」PASS。

### 訂正1：結論が証拠より広かった
- tech-lead の spike が試したのは、AI に文を作らせる形だけだった。
- reviewer は「抜き出し」の形を試した。ページの文に番号を付けて渡し、AI に3つ選ばせて、本文の文をそのまま出す形。
  - Mac で 12/12 が有効で、1回 1〜1.8秒。出すのは本文の文なので、作り話は形の上で0。
  - ただし、毎晩撮る1ページだけなら、最後の3文（AI なし）とほぼ同じになる（3文中2文が重なる）。数ページ分では前半の文に寄り、中身の薄い文も選ぶ。
  - AI なしの最後の数行より役に立つかは、確かめていない。
- 裁定 12：「端末の AI は v1 に入れない」を、「AI に文を作らせる機能は v1 に入れない」に狭める。Takuma の答え（入れない）は、文を作らせるあらすじへの答えとして残す。抜き出しは、別の問いとして Takuma に聞く。

### 訂正2：「いちばん強い反論」が、推す案への反論になっていなかった
- 4 の2「ローカル AI は、今の品質では売りにできません」は、推す案を支える理由で、推す案（AI を入れない）への反論ではなかった。
- 「AI を入れない」へのいちばん強い反論は、次のとおり。
  - spike は合成の4場面と Mac で行い、判定したのは1人だった。
  - 誤り22件のうち14件は、3つの型（父や店の取り違え、「翌朝」、「見せた」の主語）の繰り返しだった。
  - 文を作らない抜き出しの形は、試していなかった。
  - その結果、Takuma が頼んだローカル AI が、v1 にまったく入らない形で伝えた。
- 61% は、「36件中22件（4場面×3つの出させ方。厳しく数えると17件、47%）」と読み替える。
- それでも、文を作らせるあらすじを入れない判断は変わらない。
  - reviewer が、読み取りの崩れのない文で試しても、8回中6回に誤りが出た。
  - 同じモデルで1文ずつ検査させても、出す文の23%に誤りが残った。

### 訂正3：有料の「辞書」は、審査ガイドライン 4.10 に当たるおそれがある
- 4.10 は、OS の機能そのものに値段を付けることを禁じている（"You may not monetize built-in capabilities provided by the hardware or operating system"）。
- 端末の辞書の画面（UIReferenceLibraryViewController）には、アプリが足す価値がない。
- 裁定 13：辞書の画面は無料の側に置く。
  - 有料にするのは、アプリが足す処理。撮ったページに重ねる読みがな、ルビを除いた読み上げ、言葉の手帳の記録と並べ替え。
  - 値段を決める前に、App Review に問い合わせる手順を PRD に書く。

### 直すとよい（4〜7）
- 4：AI を見直す道は、PCC、抜き出し、1文ずつの検査と主語を必ず書かせる指示、の3つ。
  - 見直すときの合格の線の案：本物の文庫20晩分で、出した文のはっきりした誤りが1件以下。
  - iOS 26 のモデルでも、同じ線で測る（今回の数字は、どれも macOS 27 のモデル）。
- 5：判断2の理由は、審査ではなく、届く人の数と品質。
  - 3.1.2 は定期課金の決まりで、買い切りには当たらない。
  - 買い切りに当たるのは 2.3 と 2.3.2（何に払うかを、はっきり示すこと）。
- 6：対応機種の割合は、「約4〜5割（2026年8月に持っている機種。言語の設定によっては、実際に使える人はこれより少ない）」と書く。
- 7：撮ったページの読み取った文を、端末の中にどれだけ残すかを、G1 の ADR で決める。著作物の扱いは要確認で、Takuma を通す。
