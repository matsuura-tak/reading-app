# 「夜の入口、本の出口」をお金になる形にする案（pdm、調べもの、2026-10-18）

## 結論
1. 推すのは**案1：芯は無料のまま、見た目と「一冊のしおり帳」を買い切りで売る（仮の名前「しおりどき＋」、¥980［推測］）**。定期（案2）と、AI だけの定期（案3）は推しません。
2. 毎晩の入口（ロック画面の一行、伏せて読む、しおり）と、読み終えた夜（奥付、受賞、次の1冊）は、有料の壁の外に置きます。購入の案内は、利用者が自分で開いたときだけ出します。無料のものを、後から有料に移すことはしません。
3. 課金は v1.0 から始めます。条件は2つです。G1 までに国立国会図書館サーチ（書誌の出どころ）の営利の扱いが片付くこと。tech-lead が見積もった追加の日数を、Takuma が作る期間として受け入れること。片付かなければ v1.0 は無料で出し、公開42日後までの v1.1 で課金を足します。
4. 入る額は小さい見込みです［推測］。1年で1.5万ダウンロード、その3%が買うと、手取りは約34万円です。月 $1K（約15万円）には届きません。新しいアプリで、2年以内に月 $1K に届くのは17.3%です［公開情報］。
5. いちばん強い反論：読書の道具は、日本では稼げる型ではありません。ブックの売上の上位25はすべて、作品の販売か Audible です。道具のアプリは43位と70位台が最上位です。お金を主な目的にするなら、別の pdm が調べているローカル AI の方向と並べて決めるべきです。

## 3. 有料にする所の候補

| 候補 | どこに置くか（推奨） | 理由と根拠 |
|---|---|---|
| 毎晩の入口（ロック画面の一行のウィジェット、伏せて読む、「読み始める」、しおり、予約した Live Activity、基本の StandBy） | **無料（壁の外）** | North Star（週に2晩以上読んだ人の数）は、入口を毎晩使う人から生まれる。壁の中に置くと、価値が伝わる前に習慣が止まる［推測］。ToRead はロック画面の表示を Plus に入れているので、ここを無料にすること自体が違いになる［公開情報 product.md の 4］ |
| 読み終えた夜（奥付、受賞、次の1冊とその理由の1文、基本の読み終えのカード） | **無料** | I-3（本から本への継続率）の芯。次の1冊がないと、翌晩の戻り先がなくなる（product.md の 2） |
| 積読に入れられる冊数の上限 | 置かない | 次の1冊への道をふさぐ。ブクログの「結局課金しないとほとんど使えない」 |
| 見た目（明朝の書体の種類、紙の色、ウィジェットと StandBy の意匠、カードの型） | **有料の芯** | アイデアの「読む時間そのものが美しくなる」に合う。この分野でお金が払われているのは着せ替え（ネコノホンシツジのコイン、mekuru のしつらえ、Forest の木）。ただし無料の既定の見た目も美しくする。ポートフォリオや ADA の審査で見られるのは、無料の画面［推測］ |
| 一冊のしおり帳：読み終えた本の、晩ごとの日付、分、止めた一行が縦書きで並ぶ。自分だけで見る | **有料** | 本の出口の記念で、「本を読む人でいる自分を確かめる」（人の目の面）に効く［推測］。人に送らないので、私的使用の見込み（PRD の 17）。書き出しと共有は持たない。晩ごとの一行を v1 のデータに残すかは tech-lead に要確認 |

| ウィジェットの種類 | ロック画面の長方形（主の入口）は無料。それ以外の大きさと意匠は、上の「見た目」に入れる | ToRead と逆の線 |
| 統計 | 作らない | product.md の 1（蔵書の統計は持たない） |

| 広告 | 入れない | 読書の前後に割り込む（Yomoo とネコノホンシツジの不満）。入る額も小さい［推測］。国立国会図書館の申請が要るのは課金と同じ |
| 書店へのリンク（アフィリエイト） | v1 では入れない | 読書メーターの「露骨な販促の動線が鬱陶しくて萎えます。」。openBD の条件（PRD の 16）。新しい本の候補が増える v2 で考え直す |

- r2 で PRD に足す決まりの候補（AC にするのは r2）
  - 購入の案内は、利用者が自分で開いたときだけ出す。たとえば、設定の「しおりどき＋」を開いたときや、鍵の付いた見た目を押したとき。
  - 毎晩の道（ロック画面を押してから読み終えるまで）と、読み終えた夜の流れでは、案内を1回も出さない。
  - 無料のものを、後から有料に移さない（product.md の 5 の「守ること」に足す）。
  - 無料の試用期間を置かない。買い切りなので、自動で更新されることもない。
  - 設定に購入の復元を置く。3.1.1 の文：「you should make sure you have a restore mechanism for any restorable in-app purchases」［公開情報 https://developer.apple.com/app-store/review/guidelines/ 、Last Updated: October 16, 2026、2026-10-18 に curl で確かめた］。
  - 有料の項目は、ストアの掲載文とスクリーンショットで有料だと分かるようにする（2.3。文言は reviewer に要確認）。

### 5-1 3つの案

### 5-3 推す案：案1
- 案2は、計算の上では約2倍の額になります。それでも推さない理由は3つです。
  - 定期が主のアプリは、レビューで不満が多い（星3以下が48%）。
  - 年額の解約が増えている。原文：「~56% of annual subscribers cancelled in Year 1 in 2025, while this worsened to ~72% in 2026」（RevenueCat 2026）。
  - サーバーを持たない v1 には、定期の根拠になる、続く費用と続く価値が薄い。
- 定期が自然に合うのは、v1.x で友人の気配（毎月のサーバー代）を足すときです。mekuru のオーナーの定期と同じ筋です。
- 案1から案2へは、後から移れます。条件は、買い切りで買った人が使い続けられることです。ガイドライン 3.1.2 に、「full game unlock」を買った人に配慮する例の文があります。なので、この判断は元に戻せます。
- 案3は推しません。端末の中の AI は1回ごとの費用がかからないので、定期にする理由が弱いです。対象の機種も限られ、AI を嫌う声もあります。AI は案1の有料の中身の1つとして足します。

### 5-4 v1 で課金を始めるか
- 推奨：**v1.0 から始める**。
  - v1.0 の有料の中身は「見た目」だけにします。すでに作るウィジェットとしおりの画面の、別の版を作るだけなので、いちばん安く作れます［推測］。
  - 一冊のしおり帳は、晩ごとの一行を v1 のデータにもう残すなら v1.0 に、そうでなければ v1.1 に入れます。
  - AI のふりかえりは v1.1 に入れます。
- 理由［推測］
  - 公開直後のダウンロードの山で、熱心な人が払える。私は積読家には「早速課金しました！」という声があります。
  - 購入の仕組み（StoreKit、復元、購入の画面）にかかる手間は、今作っても後で作っても同じ。
- 条件：G1 までに、書誌の出どころの営利の扱いが片付くこと。tech-lead が出す追加の日数を Takuma が受け入れること。今でも見積もりは17〜20日で、2週に入っていません（tech-lead r1 その1 の指摘3）。
- 条件がそろわなければ、v1.0 は無料で出します。「ずっと無料のもの」と「有料にするもの」の線は v1.0 の前に PRD に書き、公開42日後までの v1.1 で買い切りを足します。
