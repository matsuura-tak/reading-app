## 結論
- 4体とも、同じ形を推した。
  - 毎晩は「続きの一行 → 伏せて読む」だけにする。
  - Takuma の4つは「1冊を読み終えた夜」に集め、次の本へ途切れずに渡す部品にする。
  - pdm の名前は「夜の入口、本の出口」、designer の画面の形は「一冊のしおり」（1画面、タブなし）。指揮役は、2つを1つの案として推す。
- v1 はサーバーなし（月0ドル）で作れる。tech-lead の見積もりは約10日［推測］。
  - サーバーか iCloud の共有が要るのは、友人と、本当の意味の「これを読んだ人は」の2つだけ。この2つは v1 から外す。
  - 友人の代わり：「読み終えのカード」を画像で送る形。
  - 「これを読んだ人は」の代わり：事実の理由つきの「次の1冊」（積読、同じ著者、同じ賞、同じレーベル）。
- いちばん強い反論：主役の続きの一行が、「毎晩、止めたページを撮る」手間と、まだ確かめていない読み取りに頼っている。

## 2. 推す形
### 毎晩（数十秒以内）
1. 夜、ロック画面に、昨夜止めた所の一行が縦書きで出る。出し方は、ウィジェット（主）と、予約した Live Activity（iOS 26 から）。
2. 押して開き、iPhone を伏せる。読書が始まる。
3. 起こして終えると「p.43 → p.61　18分」と出る。止めたページを撮って、止めた行を押す。撮らずに、ページ数だけを入れる道もある。

### 1冊を読み終えた夜（1分ほど）
1. 「読み終えた」を押すと、奥付の形で5行まで出る（書名、著者、出版社、初版の年、受賞）。
2. 読み終えのカード（何晩、合計の時間、最初と最後の一行）を、画像で LINE などに送れる。
3. 次の1冊を3冊まで出す。理由は事実1行にする（例：「積読から。同じ著者」「同じ本屋大賞の、次の年の受賞作」）。
4. 選んだ本が、翌晩の続きの一行になる。

### Takuma の4つの置き場所
| Takuma の言葉 | v1 | 後の版 |
|---|---|---|
| 続きの一行（1機能としてあり） | 主役。ロック画面のウィジェット（縦書き）、予約した Live Activity、充電中の StandBy | - |
| 本を簡単に登録できる | バーコードの連続、書名で探す、手で入れる | 背表紙の写真から何冊も（確かめ1しだい）、ほかのアプリからの取り込み |
| 出版社が知りたい | 奥付の1行（出版社とレーベル） | - |
| 何の賞を取ったか | 芥川賞、直木賞、本屋大賞（手で作る一覧） | ほかの賞（江戸川乱歩賞、Booker など） |
| これを読んだ人はこういうのがおすすめ | 「次の1冊」（積読、同じ著者、同じ賞、同じレーベル。理由は事実1行） | 友人が読んだ本（v1.x）。読み終えた人が一定数を超えた本だけに出す、本当の「これを読んだ人は」（v2） |
| 友人が何を読んでいるか | 読み終えのカードを画像で送る | 友人の気配（今夜開いたか、読んでいる本の題。20人まで。v1.x、確かめしだい） |

### Apple Design Award
- 主に Interaction、従に Inclusivity を狙う（designer の 6-4）。
- 読書のアプリは、2025年と2026年の受賞作にも最終候補にもない。

## 3. 4体で分かれた所と、指揮役の裁定
1. **受賞を v1 に入れるか**
   - tech-lead は v1（3賞）、pdm は v1.x を推した。
   - 裁定：v1 に入れる（3賞）。Takuma が名指しした機能で、利用者が0人の日の「次の1冊」の理由にもなるため。2週間からあふれたら、最初に削る。
2. **友人を、読む前（ロック画面）にも見せるか**
   - pdm はロック画面に「今夜、2人が読んでいます」を出す形、designer は読んだあとだけに出す形を推した。
   - 裁定：今は決めない。友人の機能（v1.x）を設計するときに決める。
3. **「今夜の量」「あと何晩」を v1 に入れるか**
   - designer は v1、pdm は v1.x を推した。tech-lead の見積もりには入っていない。
   - 裁定：v1.x。
4. **本当の「これを読んだ人は」を出す人数の線**
   - designer は20人、pdm は30人を例に挙げた。tech-lead は、意味のある数になるには利用者が数千人を超える必要があると見ている［推測］。
   - 裁定：v2 の PRD で決める。
5. **受賞の一覧を作る役**
   - tech-lead の見積もりは1〜1.5日。
   - 裁定：v1 の PRD のときに決める。法務の確認は Takuma を通す。

## 4. いちばん強い反論
1. **主役が毎晩の手間に頼る。**
   - 止めたページを撮るのは約5〜8秒かかる。
   - ルビの付いた漢字は、読み取りで崩れる。最後の行の位置は 4/4 正しく取れた（tech-lead の spike。合成の画像）。
   - 撮らない夜が続くと、ロック画面は書名とページだけになり、ほかのアプリと同じになる（designer の 7-3）。
2. **4つは大手がすでに持っている。**
   - Goodreads は4つすべて、ブクログはほぼ4つを持つ。
   - 日本で SNS が主の新しい読書アプリは伸びていない（Shelfie 10件、Reads 176件）。
   - 静かな友人の気配も、mekuru（370件）がすでに持つ（pdm の 5）。
3. **4つはどれも「何を読むか」の機能で、小さいつまずきに当たる。**
   - いちばん大きいつまずきはスマホ（43.6%）と疲れ（38.9%）。4つが当たるのは、迷う（3.6%）の方。
   - 友人とおすすめは、アプリの中の時間と、積読を増やす向きに働く（需要の 8）。
- **試作との違い**
  - 10秒の試作（c1）は、一行を画面いっぱいに描いた。
  - 実際のロック画面では、時計の下の小さな枠（172×76pt。15〜25字の句）になる。
  - 大きく出るのは、枕元で充電しているときの StandBy（designer の 1-0、tech-lead の 5）。

## 5. 確かめの追加（推す3つ）
| 確かめ | 誰が | 手間 | 合格の線 | 効く判断 |
|---|---|---|---|---|
| 文庫のページを5枚撮る（本棚の写真と一緒に渡す） | 写真は Takuma。読ませるのは tech-lead（リポジトリの外で扱い、終わったら消す） | 5分 | 5枚中4枚以上で、最後の行の位置を正しく取れる［指揮役の案。tech-lead に確かめる］ | 主役の写真の道を v1 に残すか |
| 7晩の記録に1項目：「止めたページを撮ってもよいと思ったか（はい／いいえ）」 | Takuma | 1晩数秒 | 読んだ夜のうち7割以上で「はい」［指揮役の案］ | 写真を主の道にするか、ページ数だけを主にするか |
| 5人への聞き取りに1問：「最後に1冊を読み終えたあと、次の本を読み始めるまで何日空きましたか。次の本は何で知りましたか（友人、書店、帯の受賞、SNS、Amazon、積読）。」 | Takuma | 1人2〜3分 | 3人以上が「7日以上空いた」なら、本の出口を v1 に残す。「友人」が2人以上なら友人を、「受賞」が2人以上なら受賞を、後の版の先頭にする（pdm の 5） | 本の出口と、後の版の順番 |

- 合格の線は、結果を見る前に決める。結果を見てから動かさない。
- 友人と7晩、LINE で送り合う確かめ（pdm の T5）は、友人の機能を作る前に行う。今は足さない。Takuma の手間を増やしすぎないため。
