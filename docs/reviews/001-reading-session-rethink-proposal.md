## 結論
- pdm と designer は、別々に考えて、ほぼ同じ形にたどり着いた。tech-lead の spike も、この形を裏付ける。
- 推す形：**「名前で迎え、奥付で送る」**（登録という作業をなくし、本の情報は要る時に、手元の本から写す）
  1. **迎える（加えるとき）**：背か表紙を1枚写し、書名の行を押す（著者の行も押せる）。棚から抜かなくても背で写せる。1冊6〜10秒［推測］。「名前を打つ」は同じ画面にいつもある。
  2. **読む（毎晩）**：何も取らない。毎晩の道（ロック画面の一行 → 押す → 伏せる）は0秒のまま。
  3. **送る（読み終えた夜）**：最後のページの奥付を写し、出版社、レーベル、出版年を足す。写すかどうかは利用者が決め、飛ばしてもあとで本の画面から写せる。
  4. **積読**：1冊ずつ写すか、本棚の1枚の写真で、背の書名を押した数だけ加える（アプリが背を自動で分けることはしない）。
  5. **今の本だけ「あとで」**：名前なしで今夜から読める。名前は遅くとも読み終えた夜に奥付から入る（ウィジェットは決定 66 の「今の本」）。
  6. 通信は0件。書誌データの同梱、端末の AI での振り分け、バーコードは使わない。
- なぜ良い体験になるか
  - 表紙で始め、ページで挟み、奥付で閉じる。同じ「写して、押す」手つきが1冊の始まりと終わりをつなぐ。10秒で話せる（「本がそのままデータになる」）。
  - 手間を、読む本にだけ払わせる（積読の1冊ずつに奥付を開かせない）。
  - 奥付は、いちばん手間のない時（読み終えた夜、そのページが開いている）に取る。読み終えた画面の奥付が、データベースの値でなく自分の一冊から写した値になる。結末が目に入るおそれも消える。
  - 「見つからない」「違う本を当てる」が仕組みの上で起きない。読めなければ「名前を打つ」に落ちるだけで、止まらない。
  - 作るものが減る。撮る道と同じ部品1つで、加える・まとめて加える・奥付をまかなえる。通信、順番待ち、問い合わせ直し、出どころの表示、国立国会図書館への連絡、申請の問いが消える。
- 根拠になる spike（tech-lead。合成の画像なので上ぶれする）
  - 表紙：書名と著者の行が別々に出る（帯の文とくっついたのは 0/21）。「押せば入る」形は作れる。自動で選ぶと 12〜13/21 なので、選ぶのは人。
  - 背表紙：字が約18px 以上なら書名が9割前後読める。著者は弱い（候補にとどめる）。
  - 奥付：5項目がそろう唯一の場所（前回：3項目そろいは写真に寄せた条件で 5/8）。
  - iOS 26 のシミュレーターで、日本語の縦書きを端末の中で読めることを確かめた。
- いちばん強い反論
  - 本物の本で読めるかは、まだ誰も確かめていない。飾り文字、帯、夜の明かりで崩れると、打つことになる（1冊8〜15秒）。
  - 積読10冊は約1〜1.5分［推測］で、国立国会図書館を使う今の形（40〜60秒）より遅い。「向けるだけで全部埋まる」には届かない。
  - 奥付を写さない人の奥付は書名と著者だけになり、「同じレーベル」の理由はほとんど出なくなる。
  - 読み終えた夜は余韻の時間で、奥付の作業は飛ばされやすい［推測］。
- それでも推す理由：毎晩の道は変わらない。失敗しても止まらない。出す前なら設計の書き直しだけで済み、あとから国立国会図書館を「選んだ人だけ」の形で足すことも、思い切った案 I を足すことも、同じ部品の上でできる。

## 3体で分かれた所と、指揮役の裁定
1. **バーコード**
   - pdm と designer：使わない。通信しなければ、読んでも ISBN の番号しか出ず、ほかのアプリの動作（書名が出る）への期待を裏切る。
   - tech-lead：残す。ISBN で重なりを確かめられる。2段目のコードから文庫・新書・単行本の別と「小説か翻訳か」が確かに取れ、ISBN の出版者記号の表で出版社とレーベルの候補を出せる（JAPAN/MARC の1週分で 94.5%、77.8%）。
   - 裁定：**v1.0 では使わない**（前の裁定「残す」を取り下げる）。理由：加えるときに裏返して2回写す手間が増えるのに、得られるのは候補だけ。確かな値は読み終えた夜の奥付で取れ、重なりはそろえた書名で確かめられる。tech-lead の2段目と出版者記号の調べは、v1.1 の候補として記録に残す。Takuma に確かめる（下の 2）。
2. **本棚の1枚の写真から何冊も**
   - pdm：写真1枚の確かめで線に届いたときだけ。designer：入れる（自動では分けない）。tech-lead：手間 +1.0〜2.0日、書名は読めるが本ごとの組は弱い → 「書名を押して加え、著者は候補」なら安全。
   - 裁定：**v1.0 に入れる**。形は designer と tech-lead の線（押した書名の数だけ本になる。自動で分けない。著者は候補）。Takuma の本棚の写真（確かめの計画の 1。結果待ち）が届けば読ませて見え方を決め、届かなくても1冊ずつの道があるので出せる。
3. **「あとで」（名前のない今の本）**：pdm と designer とも「今の本1冊だけ認める」。裁定：そのとおり。
4. **思い切った案 I「登録のないアプリ」**（読み終えた夜に積読の山を写すと、次の1冊の背に札が付く）：designer は v1.1 の向きとして残す。裁定：v1.1 の候補として product.md の版の地図に書く。芯の「次の1冊」を未確認の背の読み取りに頼らせないため、v1.0 には入れない。
5. **本物の写真の確かめ**：Takuma は奥付10冊の確かめを「行わない」と決めた。裁定：G2 の前には頼まない。精度は G4 の実機の確かめの中で見る（pdm の V-2、V-3。約15〜20分。見せ方だけが変わり、AC は変わらない）。
