## 4. 親向けで出すか、Kids（子ども向けの区分）で出すか
ガイドラインの本文は 2026-10-16 に開いて読みました［公開情報 https://developer.apple.com/app-store/review/guidelines/ ］。tech-lead の報告（docs/reviews/001-reading-session-angles-tech-lead.md の④）と合わせると、次のようになります。

| 決まり | Kids に入れる場合 | 親向け（Kids に入れない）場合 |
|---|---|---|
| 1.3 | 外へのリンク、購入、子どもの気をそらすものは、保護者のゲートの奥に置く。外部の解析と広告は原則入れない（限られた例外あり）。個人を特定できる情報や端末の情報を第三者に送らない。「一度 Kids の決まりを守ると期待されたら、区分を外しても、その後の更新で守り続ける」 | かからない |
| 2.3.8 | 「For Kids」「For Children」にあたる言葉を使える | 使えない。アイコン、スクリーンショット、プレビューを 4+ に合う絵にする決まりは、どちらにもかかる |
| 5.1.4 | 子どもから個人データ（例：写真、動画、そのほかの個人データ）を集める、送る、または共有できるなら、プライバシーポリシーを置き、子どものプライバシーの法令に従う。保護者のゲートは、保護者の同意を取ることとは別物 | 同じ決まりがかかる。加えて、Kids 以外のアプリは、名前、サブタイトル、アイコン、スクリーンショット、説明文に、主な利用者が子どもだと読める言葉を入れられない。また、「主に子ども向け」のアプリは、区分に関係なく外部の解析と広告を入れるべきでないとされる |
| 2.5.14 | 録音するときは、はっきり同意を取り、録音中だと目か耳でわかる知らせを出す | 同じ |

- **親向けで出すときの、名前とスクリーンショットの書き方**［推測］
  - 主語を親にします。例：「音読を、あとで聞いて判を押す」。
  - 名前、サブタイトル、説明文に「子ども向け」「キッズ」「小学生向け」を入れません。
  - 「小学生の音読」も、主な利用者が子どもだと読まれるおそれがあります。どこまでよいかは tech-lead に判断してほしいです。
  - スクリーンショットの1〜3枚目は、親が聞いて判を押す画面にします。子どものキャラクターやスタンプを主役にしません。
- **2.5.14 と「伏せて置く」はぶつかります。** 伏せると、録音中の表示が画面ごと見えなくなります。始まりと終わりを音で知らせるなど、耳でわかる知らせが要りそうです［推測。designer と tech-lead に確かめてほしい］。
- **pdm は親向けを推します**［推測］。
  - 理由
    - 操作するのも払うのも親です。designer の「象徴の瞬間」も、親が判を押す場面です。
    - Kids は区分を外したあとも決まりが残るので、元に戻しにくい選択です（1.3）。
  - いちばん強い反論：子どもの声を扱うので、審査で「主に子ども向け」と見なされるおそれがあります。そうなると、区分に関係なく外部の解析と広告を入れられません。
  - 手当て：どちらの区分でも、外部の解析と広告は入れない前提で設計するのが安全です。r1 の Q4 (b)（外部の解析を入れる）は見直しが要ります［推測］。
