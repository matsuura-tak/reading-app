## 結論（2体がそろった所）
1. **「本物」（他人の読書から作る推薦）は作れる。ただし、公開の日には0人なので何も出ない。** 出せるのは仕組みまでで、人数がそろった組から順に出る。
   - 1年目に組を送る人は、中くらいで約790人［推測。pdm］。読み終えた本に「読んだ人」の組が出る割合は、送る人1,000人で0〜26%、1万人で25〜48%［推測。2体の模型はおおむね合う］。
   - 機械学習は、この人数の壁を越えない。
2. **推す形：同意した人の「読み終えた順の組」だけを、人と結び付けずに集め、しきい値を超えた組だけを月1回の表にして、書誌データと同じ道（Background Assets）で全員の端末に配る。**
   - 送るもの：直前に読み終えた本と、いま読み終えた本の2つの番号だけ。時刻、一行、ページ、分数、端末の ID は送らない。
   - 範囲：文学（NDC 9）の本どうしの組だけ（病気、宗教、性の本から内面を推し量られないため）。
   - 出す条件：10人以上がそろった組だけ。人数は画面に出さない（更新のたびに1増えるのが見えると、人を当てられる）。
   - 見る側の端末は、何も問い合わせない。
   - 既定はオフ。同意は、本を1冊読み終えたあとに1回だけ聞く。「足さない」人には二度と聞かず、設定にだけ置く。足さない人も、出た行は全員が見られる（有料の条件にもしない。5.1.1(ii)）。
3. **「サーバーなし」と「本物」は両立しない。** Apple が第三者のアプリに出している匿名の集計や中継の仕組みは、文書で見つからなかった。集める場所が要る。
   - 推すのは自前の最小のサーバー（受け口1つ。組ごとの数を足すだけで、生の記録も IP も残さない。Cloudflare Workers と D1 の無料の枠で、利用者1,000人なら月0ドル、上限を広げて月5ドル）。
   - CloudKit の公開データベースは、書いた人の iCloud の記録に結び付き（匿名にならず、プライバシーの表示が「ユーザに関連付けられたデータ」になる見込み）、iCloud のない人は送れず、集計の仕組みもない。
4. **機械学習（端末の中）**
   - NLContextualEmbedding は日本語で動いたが、小説では書名だけでは型をほとんど知らない（効き目は控えめ。本の分野の当たりは 0.28 対 規則 0.17）。シミュレーターでは動かない。実機は未確認。
   - MLRecommender は1人分のデータでは推薦0件。Foundation Models は前の spike で規則より悪い。
   - 日本語の読書の記録で営利に使える公開データはない。
   - 結論：v1.0 の推薦の芯は規則（同じ著者、次の巻、同じ賞、同じレーベル。同梱データで持っていない本も）。端末で学べるのは、その人の好み（理由の種類ごとに「選んだ／見送った」を数えて並べ替える）まで。埋め込みでの並べ替えは、Takuma の iPhone で確かめてから v1.x。
5. **言い方**：掲載文、スクリーンショット、審査メモで「AI」「機械学習」とは書かない。何から出るかを書く。競合（ブクログ、StoryGraph）の低評価レビューに、記録を AI に使われることへの反発が繰り返し出ている。
6. **変わること**：プライバシーの表示が「データの収集なし」から「ユーザに関連付けられていないデータ」に変わる（同意制でも避けられない）。審査 5.1.1 の同意と取り消し、外部送信規律への答え（同意を取る形）、サーバーの運用（毎月 0.25〜0.5日）、固定費（年 約¥15,000 → 約¥15,000〜60,000）。backend/ を使い始めるので、app.json の stacks も Takuma に直してもらう。

## 2体で分かれた所と、指揮役の裁定
1. **集め始める版**
   - tech-lead（甲）：v1.0 から。冷たい始まりを縮める手は、早く集め始めることしかない。
   - pdm（B）：法の確かめ（外部送信規律、個人情報保護法）が済んだ版から。目安は v1.1（公開から6週以内）。G2 までに済めば v1.0 に前倒し。6週遅れても1年目の送り手は1割ほどしか減らない［推測］。
   - 裁定（推奨）：**B**。理由：Takuma は 2026-10-20 に、書名と ISBN を外に送ることさえ「法的リスク」として退けた。読書の記録はそれより私的なデータなので、専門家の確かめを待つ価値がある。v1.0 の「データの収集なし」も守れ、v1.0 の枠（要る速さ 2.94〜4.32倍）も増やさない。出す側の部品（表を読み、行に足す）は v1.0 から入れておけば、集め始めたあと更新なしで出る。
2. **しきい値**：tech-lead は 5〜10、pdm は 10（Apple の分析の5人の倍）。裁定：10。
3. **PRD の分け方**：pdm は、集めて出す機能を別の PRD（002）にする案。裁定：採る。同意、送信、サーバー、法律、撤退の線が 001 の芯と別で、承認済みの 001 の 13 と 14 を動かさずに済む。001 には「読んだ人」の行の置き場所と言い方の決まりだけを足す。
