## 1. 結論と推す案

**推すのは案 G「名前で迎え、奥付で送る」です。** 本の情報を、要るときに、そのとき手元にある本の場所から、利用者が選んで取ります。外部の API も通信も使いません。

取る時を、本の一生に合わせて3つに分けます。
- **迎える（加えるとき）：名前だけ取る**
  - 背か表紙を1枚写し、書名の行を押します（著者の行も押せます）。
  - 棚から本を抜かなくても、背なら写せます。
  - 押す回数は3〜4回で、1冊約6〜10秒です［推測］。
  - 「名前を打つ」はいつも同じ画面にあります。
  - 今の本がないときだけ「あとで」を出します。押すと、名前のないまま今夜から読めます。
- **読む（毎晩）：何も取らない**
  - 毎晩の道（ロック画面の一行 → 押す → 伏せる）は0秒のままです。
- **送る（読み終えた夜）：奥付から取る**
  - 出版社、レーベル、出版年は、最後のページの奥付を写して取ります。
  - 写すかどうかは利用者が決めます。写すなら約8〜15秒です［推測］。
  - 名前のない本は、ここで書名と著者も入ります。
- **やめるもの**
  - バーコードとISBN。本の重なりは、名前で確かめます。
  - 「道を選ぶ」画面（S-8）。「本を加える」を押すと、そのまま写す画面が開きます。
- **積読を足すとき**：同じ部品で、1冊ずつ続けて写すか、1枚の写真に写った背の書名を押していきます。押した数だけ本になります。
- **読めないとき**：どの場面でも「名前を打つ」に落ちるだけです。「見つかりません」も、通信の待ちもありません。

**いちばん強い反論**
1. 背と表紙の文字を読めるかは、本物の本では確かめていません。
   - 飾った字体、帯の宣伝の字（R-57）、細い背、夜の明かりで崩れるおそれがあります。
   - 崩れたら打つことになり、1冊8〜15秒かかります。
2. 積読10冊は約1〜1.5分かかり［推測］、国立国会図書館を使う今の形（40〜60秒）より遅いです。自動で埋まるという当たり前の品質には届きません（pdm の 4）。
3. 奥付を写さない人の奥付は、書名と著者だけになります。「同じレーベル」の理由も、ほとんど出なくなります。
4. バーコードという、見慣れた操作がなくなります。

**それでも推す理由**
1. 手間を、読む本にだけ払わせます。
   - 書店で本を買う人の79%に積読があります（PRD E-7）。
   - 前の案 F は、読まないかもしれない積読の1冊ずつに、裏返して奥付を開く手間（1冊10〜20秒）を求めていました。
   - G で加えるときに要るのは、名前1つだけです。
2. 奥付を取るのに、いちばん手間のない時を使います。
   - 奥付は本文が終わった後か巻末にあります（R-55）。読み終えた夜には、そのページが手元で開いています。
   - 読み終えた画面の奥付（D-2）が、データベースの値ではなく、自分の一冊から写した値になります。
3. 読み取りに失敗しても止まりません。
   - Takuma は本物の奥付の確かめを行わないと決めました。そこで、読み取りは「候補を出すだけ」にしました。
   - いちばん少ない入力は、打った名前1つです。読み取りの精度は、速さにだけ効きます。
4. 作るものが減ります。
   - 撮る道（v1.0）と同じ「写して止め、行を押す」部品1つで、次の3つをまかなえます：加える、まとめて加える、奥付。
   - 消えるもの：バーコード、通信、順番待ち、問い合わせ直し、書名で探す道、出どころの表示。
5. 元に戻しやすく、先があります。
   - あとで国立国会図書館を「選んだ人だけ」の形で足せます。
   - 下の思い切った案 I（積読の山から次の1冊）も、同じ部品の上に足せます。

**思い切った案 I「登録のないアプリ」は推しません。v1.1 の向きとして残します。** 見せ場はいちばん強いです。ただ、次の1冊は PRD で v1.1 に回さないと決めた芯です。それが、実物で確かめていない背の読み取りに頼ることになります（3-1）。

## 2. 前提の問い直し

### 2-1 本の情報は、どの場面で本当に要るか
| 情報 | 使う所 | 初めて要る時 | なくても動くか |
|---|---|---|---|
| 書名 | しおりの画面、本棚、ウィジェットの読み上げ、奥付、カード、次の1冊、受賞の照合 | 2冊目を加えたとき（本を見分けるため）。遅くとも読み終えた夜 | 動く。ウィジェットは、一行があれば書名を出さない。なければ「今の本」と出す型がもうある（決定 66） |
| 著者 | 奥付、次の1冊の「同じ著者」、受賞の照合 | 読み終えた夜 | 動く。理由は「積読から」だけになる（AC-80 の形） |
| 出版社とレーベル | 奥付、「同じレーベル」 | 読み終えた夜 | 動く。データのない行は出さない（PRD 9、AC-18） |
| 出版年 | 奥付 | 読み終えた夜 | 動く（同じ） |
| ISBN | 本の重なりの確かめ | 加えるとき | 名前で代えられる［推測］。通信がなければ、ほかに使い道がない |

わかったこと：加えるときに要るのは「見分けるための名前」だけです。ほかの情報は、どれも読み終えた夜に初めて要ります。そしてその夜には、奥付のページが手元にあります。

### 2-2 加えるときに、全部そろっている必要はあるか
ありません。足りない行は、今の決まりで隠れるか、理由の行が「積読から」になるだけで、画面は崩れません。AC-83（受賞の一覧から積読に加える本。ISBN と出版社は空）は、G ではふつうの積読と同じ形になります。

### 2-3 「登録」という作業をなくせないか
- 今の本は、なくせます。「あとで」で名前なしに読み始め、名前は遅くとも読み終えた夜に奥付から入ります（G に入れた）。
- 積読は、案 I（読み終えた夜に積読の山を写す）でしかなくせません。I は 3-1 で比べました。

### 2-4 どこから取るか（そのとき手元にある本の場所）
| 時 | 手元にある場所 | 取れるもの | 判断 |
|---|---|---|---|
| 加えるとき | 背と表紙（開かずに済む） | 背は書名、著者、出版社（R-56）。表紙は書名と著者だが、帯の宣伝の字が混ざる（R-57） | 名前だけ取る。案内では背を先に勧める |
| 最初の夜と、読むうちに | 開いたページ（撮る道） | 柱（版面の外の書名、章名、節名）とノンブル（ページの数字） | 柱は書名の取り口にしない。JLREQ に「その点では書名を掲げるのはあまり意味があることではない」とある（R-58）。ノンブルは書誌の外の案として未解決に書いた |
| 読み終えた夜 | 最後のページ＝奥付 | 書名、著者、発行所、発行年月、刷数（R-55）、ISBN | ここで出版社、レーベル、年を取る |
| 本棚をまとめて | 背の並び | 書名、著者、出版社 | G は押していく形。アプリが背を自動で分けるのは案 H、積読の山から選ぶのは案 I |

### 2-5 誰が決めるか
- 読み取りは候補を出すだけにし、決めるのは人にします。
  - 自動で欄に振り分けると、縦組みで外れます（R-51「たて名刺で、名前を横書きの郵便番号の下4桁部を認識する」）。
  - 小さい仮名と濁点は読み違えます（R-52）。
- 先に選んでおくのは、見える形で、押せば替えられるときだけにします（R-45「prefill fields with reasonable default values」）。
- AI に文は作らせません（裁定 12）。

### 2-6 バーコードは何をくれるか
通信しなければ、読んでも ISBN の番号しか出ません。ほかのアプリでは書名が出る動作なので、番号だけでは期待を裏切ります［推測］。そこで G では、バーコードを使わないことにしました（7 の決めてほしいこと 2）。

## 3. 案の一覧と比べ

### 3-1 案ごとの中身
**F 前の案「加えるときに全部」**（比べのため）
- 流れ：S-8 → バーコード → 奥付を開いて写す → 行を押す → 確かめて加える。押す5〜7回、1冊12〜20秒。積読10冊で2.5〜4分。
- そろう時：加えるときに全部。
- 読めないとき：撮り直す、別の枠を押す、欄で直す、手で入れる。
- 性格語：確かと紙の側は合う。急かさないは弱い（最初に全部を求める）。まっすぐも弱い（手数が多い）。
- 10秒の瞬間：弱い。加えるときの手続きになる。
- 独自性：奥付を撮って登録するアプリは見つからなかった（R-49、pdm の 4。網羅ではない）。
- アクセシビリティ：手で入れる道が同じ所にある。
- いちばん強い反論：読まないかもしれない積読の全部に、奥付を開く手間がかかる。バーコードで1手使っても、番号しか出ない。

**G「名前で迎え、奥付で送る」（推す）**：くわしくは 4。1冊6〜10秒、積読10冊で約1〜1.5分（1枚から何冊も押す形なら約1分前後）。読み終えた夜に写すなら +8〜15秒（写さなくてもよい）［推測］。

**H「本棚を1枚で」**
- 流れ：棚か積読の山を写す → アプリが背ごとに分けて一覧にする（書名、著者、出版社）→ 違う所を直す → n冊を加える。10冊で30〜60秒と、直す時間［推測］。
- そろう時：加えるときに書名、著者、出版社（R-56）。年は取れない。
- 読めないとき：一覧で直す。1冊ずつ写す形（G）に落ちる。
- 性格語：まっすぐは合う。確かは弱い。分け方を誤っても気づきにくい（R-51 の型）。
- 10秒の瞬間：見栄えはするが、先行がある（Passim「AIが背表紙を読み取って一括登録」R-49）。
- アクセシビリティ：一覧で直せる。ただ、背の細い字は大きい文字の人に不利。
- いちばん強い反論：PRD で外した「背表紙の写真から何冊も（確かめ1しだい）」そのもの。自動で分けた誤りが、気づかれずに残る。

**I「登録のないアプリ」（思い切った案）**
- 流れ
  - 本を加える画面がない。最初の夜は「今夜の本で読み始める」だけで、今の本は名前なしで始まる。
  - 毎晩の道は変わらない。
  - 読み終えた夜に、奥付を写す（書名、著者、出版社、年が初めて入る）。
  - 続けて「次の1冊：積読の山を写す」。写真を止めたあと、重なる事実（同じ著者、同じレーベル、同じ賞）のある背にだけ札が付く。
  - 押した本が今の本になり、名前は背から入る。
- そろう時：読み終えた夜にだけ、全部。
- 手間：1冊は、始めるとき0秒、読み終えた夜に16〜30秒。積読10冊は0秒（アプリに入れない）［推測］。
- 読めないとき：山が読めなければ「次の本を写す（1冊）」「名前を打つ」「あとで選ぶ」。
- 性格語
  - 急かさない、紙の側、静かは、いちばん合う。未読の数そのものを持たず、本棚が積読の一覧になる。
  - 確かは弱い。背を読み違えると「同じ著者」を見逃す。
- 10秒の瞬間：いちばん強い。「読み終えた夜、積読の山にかざすと、次の1冊の背に札が付く」。
- 独自性：見ていない。いちばん高い。
- アクセシビリティ：いちばん弱い。山にかざす操作は、目の見えない人には難しい。一覧（絵の I-2）と打つ道が要る。
- いちばん強い反論
  - 次の1冊（v1.1 に回さない芯）が、背の読み取りに頼る。確かめたのは合成の背の 14/14 だけ（前の調べものの I-1）。
  - 積読の決まり（AC-78〜AC-83、同じ順のときの「加えた日」）と、本棚 S-6 を作り直すことになる。
  - 図書館の本など、手元の山の外にある積読は置いていかれる。
  - 読み終えた夜が重くなる（2回写す）。

**J「帳面の型（打つだけ）」**
- 流れ：書名と著者を打つ（キーボードの音声入力も使える）→ 保存。1冊15〜27秒、積読10冊で2.5〜4.5分［推測］。
- そろう時：加えるときに書名と著者。ほかは打ったときだけ。
- 性格語：確かと静かは合う。紙の側は、読書ノートに書く慣習には近い［推測］。
- 10秒の瞬間：ない。独自性：ない。
- アクセシビリティ：いちばん強い（カメラが要らない）。
- いちばん強い反論：打つ手間こそ、競合の不満の上位（E-4）。G の中に「名前を打つ」として入るので、これだけを選ぶ理由は薄い。

**比べて捨てた小さな案**
- 柱から書名を取る：柱には章名が多い（R-58）。
- 帯から受賞を取る：受賞はアプリに入れる一覧で照らす。帯は宣伝の字（R-57）。
- 端末の AI に欄を振り分けさせる：規則より正しくならず、使える機種は約4〜5割（tech-lead の spike、裁定 17）。
- 書誌データをアプリに入れる（C）：大きさ、新刊の遅れ、毎月の更新がある（tech-lead）。
- Visual Intelligence やカメラコントロールから加える：v1.1 の候補のまま。
  - Visual Intelligence がアプリに渡すラベルは「general, high-level terms in the en_US locale」で、書名は来ない（R-61）。アプリ側で読み取りが要る。
  - カメラコントロールは iPhone 16 以降だけにある（R-60）。

## 4. 推す案 G の形（仕様の下地。確定は Takuma が決めてから）

### 4-2 7つの状態
**本を写す**
- 通常：写す前（映像、案内、写す、名前を打つ、あとで）と、写したあと（止めた写真、枠、欄、加える、加えて次の本を写す）。
- 空：読めた行が0のときは、案内の文と「写し直す」「名前を打つ」（AC-68 の型）。
- 読み込み中：ProgressView を出す。待つ間も欄は打てる（AC-94 の型）。しばらく使わないあとの最初の1回は、Mac で 22.69〜34.06秒かかった。
- エラー
  - カメラが使えないときは「名前を打つ」「写真から選ぶ」。
  - 保存に失敗したら、Form のいちばん上の行に出す。入れた字と選んだ行は残す（AC-91 の型）。
- オフライン：なし。通信を使わない。
- 権限を断られたとき：`camera.denied` と「設定を開く」「写真から選ぶ」（PhotosPicker、R-62）「名前を打つ」。
- 一部だけ読めたとき：読めた行だけに枠を付ける。書名の行がなければ打つ。
- 同じ名前の本が本棚にあるとき：欄の下に「本棚に同じ名前の本があります。」と出す。加えるのは止めない。

**奥付を写す**
- 通常：奥付の型に値を先に入れ、取った行に札を付ける。
- 空：読めた行が0なら「写し直す」「写さずに戻る」。
- 読み込み中：ProgressView。「写さずに戻る」は押せる。
- エラー：保存に失敗しても、値を残してもう一度押せる。
- オフライン：なし。
- 権限を断られたとき：「設定を開く」「写真から選ぶ」「写さずに戻る」。
- 一部だけ読めたとき：取れた行だけ入る。取れない行は出さない（AC-18 の型）。

### 4-3 アクセシビリティ
- 手で入れる道を、いつも同じ画面に置く（R-47「Offer alternatives to gestures」）。カメラを向けにくい人のために「写真から選ぶ」も置く。
- VoiceOver
  - 写したあと「12行を読みました。書名の行を選んでください。」と読み、焦点を1つ目の枠へ移す。
  - 行は読む順に並べる（縦組みは右の列から）。
  - 各行に操作「書名にする」「著者にする」「レーベルにする」を付ける。選んだ行は、値「書名」などを読む。
- 大きい文字（accessibility1 以上）では、写真の上の枠をやめ、読めた行を一覧にする。識別子は同じにする。
- Voice Control のため、枠に番号を出す。
- 枠の押せる範囲は 44×44pt 以上。重なるときは一覧の形に替える。
- 動きを減らす設定では、枠を動かさない。透明度を下げる設定では、写真の上に素材を使わない。
