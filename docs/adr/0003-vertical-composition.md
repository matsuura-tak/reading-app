# B ADR 0003：縦書き組版・4つの見た目・読み終えカード描画・端末内 Vision OCR

- 状態：承認
- 書いた役：tech-lead　日付：2026-10-25
- 関係する PRD、設計メモ、契約：`docs/prd/001-reading-session.md`（AC-27〜AC-35、AC-63〜AC-74、AC-84、AC-85、AC-94、AC-99、AC-102、AC-104〜AC-111、AC-113、AC-127〜AC-129、AC-137〜AC-142）、`docs/adr/features/001-reading-session.md`、`design/001-reading-session/tokens.md`、`contracts/hooks/h22-widget.schema.json`
- 元に戻す手間：中（組版アルゴリズムと H22 検査出力、および OCR 後処理クラスタリングは `ReadingCore` 内に局所化されているが、W-1/W-2 と S-1 の全描画テストに影響するため）

## 背景

「よむま」は日本の紙の小説に馴染む「紙の側」の佇まいを核としつつ、ウィジェットの厳しいメモリ制約（30MB）とサイズ制約（ロック画面 `accessoryRectangular` 最小 153×68pt〜最大 172×76pt、小ウィジェット `systemSmall` 最小 148×148pt〜最大 170×170pt）、アクセシビリティ（VoiceOver 単一ラベル連続読み上げ、Dynamic Type AX5、コントラスト比 4.5:1 / 3:1）、端末内完結の Vision OCR（ページ撮影・スクリーンショット選択・表紙撮影・本棚の複数背表紙・奥付撮影）、および 1080×1350px の読み終えカード画像生成を、すべて Apple 標準フレームワークと OS 標準フォントだけで実現する必要がある。

## 決定

縦書き組版は `ReadingCore.VerticalLineLayout` で純粋計算し、W-1/W-2 は最大 25 字（26 字以上は句読点優先ルールで短縮）、句読点・括弧・リーダーは縦書き専用グリフ（U+FE11〜U+FE44 等、回転角 `0`）に置換し、長音符 `ー` のみ 90 度回転（`rotationDegrees = 90`）、行頭禁則文字は前の列の末尾へ追い込む。OCR は `Vision` の `VNRecognizeTextRequest`、読み終えカードは `ImageRenderer`（1080×1350px PNG）で実装する。書体はすべて iOS 標準のヒラギノ明朝 ProN とシステムフォントを使う（外部フォント同梱なし）。

### 1. 縦書き 1 行組版エンジン（`ReadingCore.VerticalLineLayout`、AC-27〜AC-35、AC-99）

1. **対象サイズと最大 25 字の短縮規則（AC-27、AC-29、AC-35、`design/001-reading-session/tokens.md`）**：
   - **W-1（`.accessoryRectangular`）**：最小 153×68pt・最大 172×76pt。縦書きのしおりの一行（`HiraMinProN-W6` 12pt、1 列 5 字×最大 5 列＝**最大 25 字**、右から左へ列を進める）と、左端に縦 1 列の書名（10pt、最大 6 字）・左下にページ表記（`p.61` 等）を配置する。
   - **W-2（`.systemSmall`）**：最小 148×148pt・最大 170×170pt。縦書きのしおりの一行（`HiraMinProN-W6` 15pt、1 列 7〜8 字×3〜4 列＝**最大 25 字**、右から左）と、下部に横書きの書名＋ページ表記を配置する。
   - **S-1（しおりの画面 `bookmark.line`）**：保存された一行（最大 60 字）を**省略せず全文**表示する（`HiraMinProN-W3` 20pt、1 列 12〜14 字×最大 5 列、AC-29）。Dynamic Type が `accessibility1`（AX1）以上のときは、全文を横書きの複数行折り返しに自動フォールバックする（`design/001-reading-session/tokens.md` 2節）。
   - **W-1 / W-2 での 26 字以上の短縮規則（AC-29）**：
     - 保存された一行が 25 書記素クラスタ以下ならそのまま全文を出す。
     - 26 書記素クラスタ以上の場合は、**先頭 25 字以内にある最後の読点「、」または句点「。」の位置が 13 字目以降（1 始まりで 13〜25 字目）であれば、その句読点まで（句読点を含む）で切る**。
     - 13〜25 字目に「、」「。」がない場合は、**先頭 24 字＋三点リーダー `…`（1 字、縦書き時は `︙` U+FE19）の計 25 字** に縮める。
2. **欧文一行の横書きフォールバック（AC-30）**：
   - 一行にひらがな・カタカナ・漢字（CJK 統合漢字）が 1 文字も含まれない場合（英語の小説など）は、W-1・W-2・S-1 すべてで縦書きにせず横書き（左揃え）で描画する。
3. **縦書きグリフ置換と回転角（AC-28、`contracts/hooks/h22-widget.schema.json`）**：
   - 句読点・括弧・三点リーダー・二点リーダーは、角度回転ではなく以下の**縦書き専用 Unicode グリフにコードポイント置換し、回転角 `rotationDegrees` は `0` とする**：
     - `、`（U+3001）→ `︑`（U+FE11）、`。`（U+3002）→ `︒`（U+FE12）
     - `「`（U+300C）→ `﹁`（U+FE41）、`」`（U+300D）→ `﹂`（U+FE42）
     - `『`（U+300E）→ `﹃`（U+FE43）、`』`（U+300F）→ `﹄`（U+FE44）
     - `（`（U+FF08）→ `︵`（U+FE35）、`）`（U+FF09）→ `︶`（U+FE36）
     - `…`（U+2026）→ `︙`（U+FE19）、`‥`（U+2025）→ `︰`（U+FE18）
   - **90 度回転（`rotationDegrees = 90`）**：長音符 `ー`（U+30FC）および波ダッシュ・ダッシュ類のみを時計回り 90 度回転（`rotationDegrees = 90`）で描画する。
   - 小書き仮名（`っゃゅょぁぃぅぇぉッャュョァィゥェォ`）はセル内の右上寄りにオフセット配置し、`rotationDegrees = 0` とする。
4. **行頭禁則（ぶら下げ追い込み、AC-28）**：
   - 行頭禁則文字（`、。）」』ー` および置換後の縦書きグリフ `︑︒︶﹂﹄`）が 2 列目以降の列の先頭（`index == 0`）に来る場合は、その文字を前の列の末尾へ追い込み、どの列の先頭（`index == 0`）にも行頭禁則文字が来ないようにする。
5. **VoiceOver 単一ラベルとプライバシーマスク（AC-34、AC-99、AC-139、AC-141）**：
   - ウィジェット全体に `.accessibilityElement(children: .ignore)` を設定し、元の横書き文字（縦書きグリフ U+FE11〜U+FE44 を含まない元の文字列）で「`<一行>、<書名>、<ページ/位置/％>`」の 1 つの連続した読み上げラベルを付与する（AC-99）。
   - `settings.hideOnWidgets == true` のときは、W-1・W-2・W-3 から書名と一行を完全に隠し、`widget.hidden`（「しおり」／「Bookmark」）と進み具合（または経過時間）だけを出す（AC-34、AC-120）。

### 2. 4つの見た目（`AppearanceID`）と「よむま＋」（AC-104〜AC-111）
- `AppearanceID` は `default`（標準）、`kinari`（生成り）、`sumi`（墨）、`shu`（朱）の 4 種とし、すべてヒラギノ明朝 ProN とシステムフォントのまま、`design/001-reading-session/tokens.md` のカラートークン（ライト／ダーク／ハイコントラスト 3 通り、文字コントラスト比 4.5:1 以上、主操作枠 3:1 以上）を切り替える。
- StoreKit 2 の買い切り商品 ID は `jp.yomuma.plus`（¥980、非消耗型）とする。毎晩の道（S-1〜S-4）と読み終え画面（S-9）には課金要素を一切出さない（AC-104）。

### 3. 読み終えカードの画像描画とふりかえりの 1 行（AC-84、AC-85、AC-127〜AC-129）
- S-9 の `finish.card.share` で生成するカード画像は、`ImageRenderer`（360×450pt、`scale = 3.0`）により **1080×1350px** の不透明 PNG とする（AC-84）。
- カードには書名と値がある奥付項目（著者、出版社・レーベル、出版年、受賞歴、読了日、4:00 境目のユニーク晩数、合計分数）のみを描画し、**保存した本の一行（`lastLine`）、撮影した写真、およびふりかえりの 1 行文（`finish.reflection`）は絶対に含めない**（AC-84、AC-127、H24）。
- ふりかえりの 1 行（`finish.reflection`）は生成 AI を一切使わず、記録が 2 晩以上なら `finish.reflection.multi`（何晩・合計何分・一番長かった晩の日付と分数）、1 晩なら `finish.reflection.single` を文の型から組み立てて S-9 画面上にのみ表示し、記録 0 件なら非表示にする（AC-127〜AC-129）。

### 4. 端末内 Vision OCR パイプラインと速度・画像非保持（AC-65〜AC-70、AC-94、AC-113、AC-137、AC-138、AC-142）
- `VNRecognizeTextRequest`（Revision 3、`.accurate`、`["ja-JP", "en-US"]`）をバックグラウンドで実行する。
- **OCR の速度目標（PRD 12章、AC-94）**：
  - 実機での文字認識完了は、**30 分以上置いた最初の 1 回が 5.0 秒以内、2 回目以降が 3.0 秒以内**（PRD 12章）。
  - 認識を待つ間に利用者が「手入力」（`mark.manual`）または「ページ番号だけ」（`mark.pageOnly`）を押したときは、進行中の OCR タスクをキャンセルして **1.0 秒（1,000ms）以内** に入力欄を出し、後から返った OCR 結果で画面を上書きしない（AC-94、H10 `markWait`）。
- **本棚の複数背表紙（S-8d、AC-138）**：`request.minimumTextHeightFraction = 0.005` を指定して細い背表紙も検出し、端末内書誌 DB（`CatalogDatabase`）で正規化書名が完全一致 **1 件** のときだけ著者・出版社・ISBN を自動補完する。
- **画像の完全非保持（AC-69、H27）**：カメラや `PhotosPicker` から得た画像はメモリ上でのみ処理し、確認画面を閉じた瞬間に解放する。ファイル保存数（`savedImageFileCount`）も写真ライブラリ書き込み回数（`photoLibraryWriteCount`）も常時 `0` とする。

## いちばん強い反論と、それでも選んだ理由

- **いちばん強い反論**：「W-1 や W-2 の縦書きを最大 25 字に制限し、かつ外部の明朝体フォント（Shippori Mincho 等）を同梱しないのでは、長めのしおりの一行がウィジェット上で途切れ、『よむま＋』の見た目の変化も色の違いだけになって魅力が薄れるのではないか。」
- **それでも選んだ理由**：
  1. ロック画面ウィジェット（最小 153×68pt）と小ウィジェット（最小 148×148pt）の面積で 12pt / 15pt の可読性を保ちつつ文字切れ 0 箇所を保証するには 25 字が物理的な上限であり、26 字以上でも 13〜25 字目の句読点「、」「。」で自然に切る規則（AC-29）により文章の呼吸を壊さず、タップして S-1 を開けば 60 字全文が読めるからである。
  2. 外部フォントを同梱しないことでアプリサイズとウィジェットのメモリ使用量を最小限に抑え（AC-100、AC-102）、iOS 標準のヒラギノ明朝 ProN（W3/W6）と厳密に設計された 4 つの紙色・墨色・朱色トークン（`design/001-reading-session/tokens.md`）だけで十分に日本の文庫本・単行本の佇まいを表現できるからである。

## 招く悪い結果

- **これで楽になること**：
  - 句読点・括弧を Unicode の縦書き専用グリフ（U+FE11〜U+FE44）に置換するため、SwiftUI の `Text` / `Canvas` 描画で回転中心のズレが一切起きず、H22 の JSON で確定的に組版結果を検証できる。
  - 画像を一切ディスクに書かないため、容量肥大化や写真流出リスクがゼロになる。
- **これで難しくなること、守り続けること**：
  - `VerticalLineLayout` のグリフ置換テーブル、行頭禁則追い込み、25 字句読点短縮ロジック、および OCR の縦書き列（右→左）ソートとノンブル分離を `ReadingCore` の単体テストで守り続ける必要がある。
- **元に戻すときの手順と手間**：
  - 縦書き組版の列数や短縮字数を変える場合は `ReadingCore/VerticalLineLayout.swift` と `contracts/hooks/h22-widget.schema.json` を更新する（手間：小〜中、1〜2 日）。

## 見直す条件

1. G3 のウィジェット性能検証（AC-102）でタイムライン項目生成の 5 回平均が **0.5 秒（500ms）** を超えるか、Widget 拡張のピークメモリが **25MB** を超えた場合。
2. G4 の実機検証（G4-12：文庫本 5 枚の撮影 OCR）において、30 分以上置いた初回が **5.0 秒**、または 2 回目以降が **3.0 秒** を超えた場合、あるいは縦書き列の右→左順序誤認が **5 枚中 1 枚以上** 発生した場合。
